# 上位机配置

`lidar_installation.json`记录用户提供的雷达安装草稿：以四轮中心O为基准，前后偏移约0、右侧约145mm；用户确认正前方向朝车体-Y、盲区朝+Y，故平面安装偏航名义值-90°。尺寸及角度误差未量化，厂家轴向定义仍待核对；扫描面离地50mm不是已标定的三维TF高度。此文件未接入执行配置，不写雷达保存位姿、不授权运动。

`mechanism_installation.json`记录用户确认的安装/料盘用途：0°基准，30°/150°/270°为三个料位；不代表完成实车标定。执行参数在`firmware/User/Config/mech_hw.h`，PWM引脚以IOC为准；PC读取这些来源显示准备清单。

后续保存地图、设备绑定、机构预设姿态与视觉标定。当前不复制旧配置，不填入未测量数据。

实车接入新增`base_trials.json`，显式标为commissioning候选，保存旧工程声明几何/极性与原始单位，不标为整机已标定。用户最新确认旧Web顺时针增加，配置v2设yaw_sign=-1。其addresses是当前四轮地址唯一来源，sync_project生成固件addresses.h并由阶段检查核对。试验目标与速度上限在正式接口和板端再次校验；候选参数不覆盖模拟场地图。

每类参数应明确唯一来源、单位、版本和适用设备；执行限位与保护参数归 `firmware/User/Config/`，硬件生成参数归 `firmware/Car.ioc`。

实际凭据与本机环境放入 Git 忽略的 `.env` 等文件，仓库仅提供必要模板。

`field_preview.json`是本轮唯一名义场地候选源：map米/弧度、主体四边偏置、净空、候选道路、工位朝向。domain=simulation且measured=false，完整包络complete=false；不能作为真实部署配置。当前蓝区可通行，起终点管理与颜色分开。新道路默认UNKNOWN，离线演示的OPEN场景在内存显式建立，不回写为实测证据。

`nominal-map-3`按用户确认固定启停区1/2为0/180°，扫码0°、原料90°、粗加工270°、暂存180°；`shared_roads`表示几何重叠的候选道路共享证据，不能分别标开放绕过未知/封路。方向确认不等于节点位置已测量。
