# 用户自助连接底盘、机械和视觉

## 日常操作

1. 树莓派、STM32和所需设备通电，树莓派与电脑连接同一网络。
2. 电脑重启后，双击工程根目录的“打开工作台.cmd”。只启动PC工作台和回环连接管理器，不自动访问SSH或设备。
3. 原8000页面顶部点击“设备连接”。首次填写SSH密码；地址和用户名沿用config/connections.json中的172.20.10.4/pi。密码只保留在连接管理器进程内存，页面发送后清空输入，不写配置、日志、诊断导出或浏览器本地存储。PC管理器退出后需重新输入，也可使用已配置的SSH密钥。
4. 设备已静止、机构有支撑时，勾选允许重开失效串口，点击“连接全部”。也可以只连接“底盘/机械”或“视觉”。等待结果；正在连接时禁止重复点击。
5. 检查STM32在线、固件/故障/停车，以及两只相机各自状态。没有插入的相机保持未就绪，不用其他video编号替代。

底盘和机械共享唯一STM32串口，并非启动两个串口进程。“底盘在线”仅表示板端通信已接入；本页底盘地图与速度控制仍是原来的模型范围，不因此宣称已开放任意实车导航。实车机械仍需自行取得控制权、接入反馈、按实物建零和进入手动模式，再明确下发目标。

## 重连范围

在线设备直接复用，即使设备有故障、有人持有控制权或正在执行动作，也不以“重连”结束会话或清除故障。只有失效/不存在的指定服务才启动或重建。重开UART可能复位STM32、使RAM现场和软件基准丢失；所以需要明确现场确认，先归档旧核心状态、运行参数文件，再正常结束已核对身份的旧进程。故障清除仍是机械页的独立人工事务，不自动执行。

连接失败、USB拔插、树莓派重启之后，由用户再次点击；没有后台无限重连、自动重试运动、自动使能、建零、回零、PC0启动或续跑。CAN、250ms反馈、保活停车和机构互锁保持。

旧零点/姿态参考失效后须按实物重新准备。线缆卡住或真实故障不能通过连续点击“连接全部”绕过。

## 结构与维护

- PC robot.connection_core：固定127.0.0.1:8094连接准备与SSH转发，8091为STM32核心代理、8092为相机代理。原8000网关重载不结束这些转发。
- Pi connection_host.py：独立部署在/home/pi/gongchuang_connection_20261027，只管理配置中已部署的两个服务；不导入串口或电机驱动，不发送目标/清故障命令，不安装固件。
- 每个模块核对/proc命令行、当前目录、端口与设备身份；同类服务多实例、其他工程占用串口或端口时拒绝接管。不强杀未知进程、不删除锁文件。
- SSH保留known_hosts校验，不自动信任未知主机。网络地址变化时修改非秘密config/connections.json，并重新启动PC连接管理器；不修改串口和相机身份映射。
- 原始状态和示教备份保存在Pi对应服务目录output/connections/唯一时间目录。连接成功不会更改已保存版本。
- PC依赖见pi/requirements-connections.txt，当前环境已有，无需再次安装。脚本不修改系统执行策略。

## 本轮验证

离线假SSH覆盖启动不连接、在线故障/活动所有者复用、过期/缺设备拒绝、双相机后接入、组件失败隔离、重复点击、同源约束、密码不回显及SSH通道暂时拒绝。50项相关Python、14组JS和1152工程检查通过。真实原8000“连接全部”已验证在线重复连接复用同一STM32身份和两个Pi进程。30.407秒86次只读检查，最大状态龄143ms、故障0/0、停车/PWM关闭；两轴尚未附着，不算动态机构验收。双相机各1280×720，8次观测7次有效、1次拒绝，未放宽250ms保护，也不作为视觉精度验收。只读窗口、截图与准备器摘要在output/connections/20261027；本轮未烧录，不自动控制设备。
