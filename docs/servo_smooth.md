## 为什么修改

本次旧板证据：P00运输收拢v2执行到第4组，组ID32、仅PE11、目标0°/100°每秒，开始后272毫秒因MECH_BASE（9）失败，最后命令估计152°；CAN真实错误、发送失败和查询超时均为0。旧板没有冻结失败瞬间的四轮反馈，因此仍不能确定是哪一轮、速度阈值还是反馈时效触发。用户观察到高速转臂伴随底盘晃动、低速不晃，与此故障入口吻合。

旧舵机每20毫秒推进固定角度，100°/秒时每步2°，起步直接进入所填速度。新版本平滑速度及加速度变化，降低机构反作用引起晃动的可能；是否消除实车故障9，需要同一姿态复测。

## 控制实现

- `Control/mech_servo.c`复用底盘已有 `Curve_Make/Curve_At` 七段S曲线。单项舵机、自动姿态和联调子舵机均走同一实现，不新建PWM所有者。
- 内部使用弧度，公共命令仍是毫度/毫度每秒。网页速度为指令速度上限，默认45°/秒，保留1～360°/秒范围。
- 初始加速度180°/秒²、加加速度720°/秒³，集中在 `Config/mech_hw.h`。这两个值是待实测的候选，不表示实测舵机能力。
- 曲线从静止参考起步、在目标处静止结束。短动作自动降低峰值；保持单调，不跨0°绕行，不反转PE11原PWM比例。
- 每次最多推进20毫秒参考时间；反馈尚未凑齐稳定轮次时沿用原等待逻辑。恢复输出后不追赶积压角度，成功应用PWM后才提交曲线进度。真正的反馈过期/轴运动/故障仍按原逻辑停止。
- 首次输出仍保持已核对的参考；一键回0°在未知初始位置时仍不能保证慢速，不冒充有真实角度传感器。
- 到达曲线末端后保留原600毫秒等待。手动命令完成只表示指令结束，人工/视觉确认和成功计数规则不变。
- 主机0.3.35单项及联调期限包含 `D/V + V/A + A/J` 保守参考时长上界，再加3秒等待/反馈余量；顺序执行器使用同一报文期限。旧版本协议期限不变。

例如：合成0→359°、上限100°/秒的参考时长约4.396秒，之后再进入原600毫秒等待；0.5°短动作即使设置360°/秒，峰值也只有约3.56°/秒。这是参考曲线数据，不是实物角度或转速证据。

## 故障9首次快照

`Board/base_port.c`在机构活动期间、更新机构停车门槛之前冻结首次失败。原 `Ready` 判定和1RPM/250毫秒门槛保持不变。

记录包括：启动内时间、原因位图、首个失败轮ID、停车确认、执行器故障、CAN计数、当前动作/通道及四轮完整反馈副本（含原位置/序号，供SWD）。GET/STOP不会覆盖记录，新启动才重新开始。

新增只读69命令、空请求、120字节返回；不扩展任何运动命令。前10个小端uint32字段为：

`schema=1 / captured / tick_ms / mask / wheel / stopped / base_fault / can_errors / action_id / channel`

随后四轮各20字节：`rpm:int32 / status:uint32 / speed_age_ms / position_age_ms / status_age_ms`。无效反馈的帧龄为UINT32_MAX。位图：1反馈无效、2超过250毫秒、4轮速绝对值大于1RPM、8驱动器异常、16停车未确认、32底层/执行器故障。未捕获时captured=0，不能解释其余默认字段为故障证据。

树莓派仅对0.3.35额外每秒读取一次69，四类关键状态继续按原节拍轮询；15毫秒合成往返测试中各关键状态间隔保持小于250毫秒。主机校验长度/版本/字段及身份，Web故障说明可显示首次轮速和帧龄；断线后不拿缓存记录授权动作。人工恢复原有归档会包含已经读到的 `park_failure`，原始快照也可在重启前通过69或SWD取得。
