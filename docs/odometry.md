# 连续里程计与主控联合模拟

2026-10-24，从`98179c3 / v0.6.0-feedback-time`推进到`v0.7.0-odometry-sim`。本轮集中完成连续观察器、端到端模拟、统一核心和Web展示；不重新排查旧CAN节点，不烧录、不清故障、不连接新的真实串口、不触发运动。

## 本轮实现

| 模块 | 实现与作用 |
| --- | --- |
| `Control/odom.c/.h` | 连续本地里程计，唯一上下文，四轮16槽位置历史＋64槽IMU历史，SI坐标X前/Y左/CCW正 |
| `device/odometry.py` | 正式C主机模型绑定，显式加载本地库；不导入工具/测试实现、不打开设备 |
| `robot/odom_sim.py` | 合成原始反馈→正式C负载编码→GC拆包/CRC→请求/时间校验与缓存→正式C里程计，对照独立解析轨迹 |
| `robot.main --odom-library` | 仅sim可加载；与现有任务账本在同一个核心调度，真实模式入口拒绝模型参数 |
| 只读Web | 单独显示模拟位姿、共同时间、提交/等待数、对照差及近期轨迹；真实顶层pose/count不填模型值 |

## 异步轮反馈的处理

旧`智能搬运小车/User/Chassis/odom.c`已实现全程连续、反馈时效、IMU历史、计数跳变、冻结待提交批次；原SHA256为`48607c8c51ac53c313ed225b3e915a23460c151f166575e5fd4c344f9c69d670`。本轮保留这些原则并抽离HAL、旧全局应用和路测速度/几何，不复制编译档位选择。

旧分轮中点法的四个计数增量仍可能对应不同起止区间。本轮先为每轮建立“接收时间→累计计数”历史，取四轮和IMU均覆盖的共同末端；首次共同起点取各历史起点的交集。每轮先插值到同一个区间两端，再转换为轮增量，避免直接把异步时间跨度当成同步数据。

积分区间在任意轮反馈或IMU历史节点处分段。每个小段采用同源轮增量和IMU起止连续角，旋转中点乘`sinc(半角变化)`，精确积分该段“轮位置线性、航向线性”的观测模型。整个区间验证成功后一次提交；缺未来覆盖就等待，早于保留历史或源失效就锁存异常，不能提交半批或偷偷重设原点。

这是接收时间上的插值模型，不代表消除了设备内部采样/传输延迟、轮子打滑或机械尺度误差。真实尺度、安装方向及完整外形未验收，输出不作为地图定位或实车动作完成证据。

## 原点、配置与保护

- 首次共同覆盖时建立局部odom原点与航向参考，保留`origin_ms`；此前未知位移不补算。后续动作没有清零接口，也不向IMU设备写零。
- 显式配置轮地址/顺序、安装极性、每圈计数、轮半径/半轴距、IMU比例/方向、速率/计数界限、时效、源代及标定版本。任一关键值未知/非法就拒绝初始化；不写入本车候选默认值。
- 位置只用编码器，航向用IMU历史；轮推算角度单独作为诊断，不再当成独立传感器重复融合。
- 同序号重报不积分、不续新鲜度；同序号冲突、逆序、源代改变、过期、角度跳变、计数跳变和历史丢失锁存失效。保留最后一次成功位姿，重新核对后才能显式新建观察上下文。
- 输入是原始驱动计数及IMU接收样本；C控制器在MCU时钟内工作，主机反馈缓存负责外层boot/session/request身份及传输时效。主机与MCU时间不直接相减。
- 每次Step最多处理`4×16＋64＋1`个区间，无无限追赶或堆分配。上下文由嵌入式唯一所有者静态保存；M4运行时间、实际RAM/栈和调度预算仍需接入后实测，主机运行快不能替代该证据。
- 接实物时，设备管理者仍需在处理前后核对ISR源代和运行预算；本算法只检查提交样本的代号，不直接读硬件状态。数值位姿有效不等于已验证地图定位精度，当前也未估计位置协方差。

## 模拟范围与入口

仅合成参数：半径0.05m、半轴距0.1/0.12m、地址11～14、混合正负极性、65536计数/圈、显式IMU比例及模型标定版本1；这些数值**不是本车参数**。模型每10ms更新IMU、每10ms仅返回一轮位置，四轮相差10ms、各40ms一次。默认先合成8秒恒定车体速度，再保持静止。

C负载经正式GC编码与拆包/CRC、严格请求校验、FeedbackCache后传入正式C观察器；观察结果与解析恒定扭量曲线比较。仿真专用反馈会话与虚拟通信板相互独立，不代表已经在真实GC固件打开0x10读接口。

```powershell
.\.venv\Scripts\python.exe -B tools/build_odom.py
$env:PYTHONPATH = Join-Path (Get-Location) 'pi'
.\.venv\Scripts\python.exe -B -m robot.odom_sim --library output/native/odometry.dll
```

报告默认`output/odometry/report.json`，保留模拟域、原点/提交时间、原始帧数、轨迹、解析对照及模型故障。Windows运行中的模型库被进程持有；更新库前停止对应本机模拟核心，或用`--output`构建新文件，不操作Pi服务。

核心联合运行示例：

```powershell
.\.venv\Scripts\python.exe -B -m robot.main --mode sim --task-demo '136+321+631+312' --odom-library output/native/odometry.dll --runtime output/preview
.\.venv\Scripts\python.exe -B -m robot.web.app --runtime output/preview --port 8000
```

模型参数在offline/serial/observer模式一律拒绝。模型每次最多追赶16个10ms逻辑步，避免仿真计算无限占用核心；任务账本仍为独立模拟物料模型，NAV步骤没有接入真实场地或根据本轨迹执行搬运，不能称为完整比赛物理仿真。真实位姿与抓放计数仍未知，模拟结果始终单独标识。

本轮本机8000为联合模拟，8001仍为上一节点的实车只读观察；两进程组和运行目录分开。`tools/stop_preview.ps1`只停止本机模拟核心/网页，旧Pi8080未改变。旧SQLite账本保留，新演示增加新模拟轮次，不删除历史。
