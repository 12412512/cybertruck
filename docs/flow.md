2026-10-24，从 `4d4a749 / v0.9.0-navigation-sim` 推进，节点 `v0.10.0-flow-sim`。本轮仅新工程离线模型、只读 Web、主机测试与 Keil 编译；未烧录、清故障、连接真实串口或触发实车运动。旧工程和 Pi8080 未改动。

## 本轮确认与坐标

统一 map：左下原点，X向右、Y向上，逆时针正；车体原点仍为名义四轮几何中心地面投影，X前、Y左。用户修正初始方向后，唯一候选源 `config/field_preview.json` 升为 `nominal-map-3`：

| 位置 | 车头朝向 |
| --- | --- |
| 启停区1、扫码 | +X，0° |
| 启停区2 | −X，180° |
| 原料 | +Y，90° |
| 粗加工 | −Y，−90° |
| 暂存 | −X，180° |

扫码相机可在车头+X时观察二维码；三个机械作业方向继续固定。蓝区可通行。取消跨区X优先和侧移不超过300mm的规划限制，长侧移和斜线也接受完整扫掠检查。位置、外形、开放道路和轮参数仍是条件模型，未转成实测配置；启停区2方向已确认，中心仍是独立名义位置。

## 连续衔接如何实现

1. 复用旧 `智能搬运小车/User/Chassis/motion/scurve.c` 的 `PathTimeMake/PathTimeSample`。源文件 SHA256：`7bae3d24d1c7a7ac139969e4e5f6c80a4b76e65668d6527af43a36a84cb116d8`。迁入现有 `curve.c/.h` 的 `Curve_TimeMake/At/Find`，统一米、秒，最多15相位；接段只改变jerk，不重置位置、速度或加速度。
2. 同一正式 `Ref/Track` 增加三种冻结参考：`POSE` 同时平移与转姿；`FLOW` 直线→曲率过渡→90°弧→曲率过渡→直线；`WINDOW` 在直线的安全窗口内低速转姿。几何方向和车身朝向分开，允许侧移转弯时保持工作区朝向。
3. 进入弯道前按距离减速，出弯再加速。末端只保留必要低速接近，不把整条返航路都压在0.025m/s。内部连接没有零速子目标，真实工位和无法安全连接的中间段仍要求停车确认。
4. 带朝向A*直接比较连续候选、可见斜线、不同转姿窗口和弯道半径，之后合并共线段、删除同一工位间的冗余点。不能跨过任务的扫码、原料、粗加工、暂存停靠点。不声称求得任意连续路径的全局最优。
5. 保留两种180°旋转方向供扫掠选取。开始下一动作时只补偿小姿态偏差，保留已选展开角方向，防止±π附近一次微小误差把旋转方向翻转。
6. `center_east/rough_approach`、`center_south/staging_approach`分别共享通行证据；任一未知或封闭，重叠边同步取保守状态，不能通过换道路名规避。存在未知/封路时禁用跨多段自由捷径，保留A*局部连接；新增轨迹穿越负例防止绕行后又切回关闭走廊。道路默认仍UNKNOWN，演示OPEN仅在内存显式建立。

线速度上限仍为 **0.14m/s**，线加速度/jerk仍为0.25m/s²、0.8m/s³。连续转姿角速度上限0.7rad/s，角加速度/jerk取更平缓的2rad/s²、12rad/s³；基准停车转向原来8/300的上限未提高。弧段另外限制向心加速度和曲率变化jerk，正式C逐次给出并检查笛卡尔V/A/J与角V/A/J。没有通过增加巡航速度制造节时结果。

扫掠使用同一正式C的全区间变化率界，自适应细分检查车体矩形与净空；独立Plant每2ms核对模拟真值。每个动作仍需零速批次确认、发送后新反馈和至少150ms稳定窗口才能完成。模型全程共享同一odom，没有在工位假清零。RefSpec扩展仅为内部C/主机模型ABI，未增加可执行的真实串口运动协议；必须把库和ctypes绑定一同重建。

## 两批范围与同速对照

默认8段：启停区→扫码→原料→粗加工→暂存→原料→粗加工→暂存→原启停区。粗加工放置和取回之间不产生额外跨区路段。

**当前模型只覆盖两批跨区导航小计，尚未建模工位内三个目标间移位、视觉精对准。** `budget_complete=false`，网页明确列出缺口；不执行扫码或搬运，不推进成功账本。完整60秒目标必须包含这些动作，不能把当前小计称为整机导航验收。

| 场景 | 模型用时 | 独立动作/停稳段 | 独立停车转向指令 | 模拟行程 |
| --- | ---: | ---: | ---: | ---: |
| 启停区1，两批停车基准 | 170.34s | 28 | 10 | 14.387m |
| 启停区1，两批连续路线 | 135.46s | 11 | 0 | 13.879m |
| 启停区2，两批连续路线 | 137.33s | 12 | 0 | 13.952m |
| 启停区1，单次五站巡回对照 | 84.78s | 7 | 0 | 8.856m |

启停区1同版本、同速度、同必经工位对照节省 **34.88s / 20.48%**。不拿上版130.97s巡回直接作两批对照，因为其范围、初始方向和末端接近策略不同。参考估计与模型实际耗时分开：连续两批参考估计136.200s，实际135.460s；网页中的“停车方案”是参考估计169.077s，实际A/B证据见本表。

“无独立原地转向指令”不表示任何时刻都有明显位移。按模型角速度>0.05rad/s且平移速度<0.006m/s统计，启停区1仍有0.352s近原地转姿，基准为25.658s；必要180°转姿仍存在，只是放入已检查的低速移动窗口。

启停区1必经点之间的欧氏距离下界约11.163m，除以0.14m/s即 **79.73s**，尚未算绕障、转姿、加减速和停车。因此当前档位无法达到完整60秒。此下界仅排除当前调试档的可行性，不给出实车许可速度；后续要补工位内运动、实际包络和载荷标定，再从路线长度、转姿区间与允许速度范围共同优化。

模型时间不含离线候选搜索/库加载的准备墙钟时间，也不等于网页5倍速播放时间。本轮规划搜索仍有明显准备开销；未来实车接入前需缓存/预计算并单独验收在线重规划时限，不能把这些开销从实车180秒中无依据删掉。
