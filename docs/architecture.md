# 整体逻辑与目录职责

## 控制链路

```text
网页 / PC0 启停
        ↓
树莓派任务管理 ── 导航、地图、A*、定位估计
        │        扫码、物料、圆环、雷达感知
        ↓
统一设备服务（唯一 STM32 串口所有者）
        ↕ USART1
STM32 应用与保护
        ├─ 底盘执行 ─┐
        ├─ 机构执行 ─┴─ 唯一 CAN 调度 ─ 电机驱动器
        └─ IMU、PWM、TJC、PC0、PB0
```

本图描述目标结构。当前已实现通信核心、独立只读Web、原子快照及STM32 USART1只读入口，并在离线域接入任务码、任务状态投影和持久事件账本。图中的实际运动、导航、机构、视觉及实车任务链路尚未接入。PC0仅上报原始按键状态。

## 运行职责

树莓派负责完整任务状态机、感知结果、路径规划、定位估计、设备所有权和网页服务，维护唯一的物料与成功计数账本。浏览器是配置与观察入口，不独占自主任务保活。

STM32 负责底盘与机构动作、反馈时效、软限位、互锁、故障与停车。下位机输出状态与结果证据，上位机根据任务规则形成成功事件。

正式任务将采用待机、手动、自主、故障等运行状态，不沿用旧工程的多套编译应用选择。当前只读固件不开放运动、建零或业务计数；上位机offline/sim/serial表示传输来源，不能等同于正式比赛模式。

后续统一动作接口区分接受、运行、完成、停车确认、失败和取消。重复消息不能重复运动或增加计数；协议字段及超时策略在通信阶段单独形成规范。

## STM32 目录

| 目录 | 职责 |
| --- | --- |
| `Core/` | CubeMX 外设初始化、启动入口与中断入口 |
| `Drivers/` | HAL、CMSIS 和芯片支持文件 |
| `MDK-ARM/` | Keil 工程、启动文件与受控工程配置 |
| `User/App/` | 统一初始化、周期调度、运行状态和互锁 |
| `User/Board/` | CAN、UART、PWM 等硬件适配，封装 HAL |
| `User/Comm/` | 树莓派协议、命令解析、应答和状态上报 |
| `User/Device/` | 电机协议、IMU、屏幕、按键和蜂鸣器 |
| `User/Control/` | 底盘、双轴、机构姿态与动作确认 |
| `User/Config/` | 执行参数、单位、保护参数及硬件适配常量 |

## 上位机与支持目录

| 目录 | 职责 |
| --- | --- |
| `pi/robot/` | 后续唯一入口 `main.py` 与任务管理 `task.py` |
| `pi/robot/device/` | STM32 串口、相机与雷达设备管理 |
| `pi/robot/nav/` | 地图、规划、定位与路径执行 |
| `pi/robot/vision/` | 扫码、物料、环位和结果确认 |
| `pi/robot/web/` | 网页接口与页面资源 |
| `pi/deploy/` | 服务与部署配置 |
| `config/` | 地图、设备绑定、姿态及视觉标定，明确版本与单位 |
| `docs/` | 接线、协议、标定步骤、阶段验收摘要 |
| `tools/` | 构建、检查、部署、诊断工具，不承载正式运行实现 |
| `tests/` | 软件测试与必要协议样本 |
| `output/` | 编译产物、原始日志、录像与临时结果，Git 忽略 |

## 参数与证据

- `.ioc` 是 CubeMX 硬件配置源；生成代码必须与它一致。
- 执行保护参数归下位机，任务地图与视觉标定归上位机；禁止两端各存一份无版本的同名有效配置。
- 旧姿态、零点、视觉参考与历史测试仅供参考，不能自动成为新任务的有效状态。
- 验证按配置、编译、通信、实物分项、完整任务分别记录。当前硬件与动作均为待验证。
