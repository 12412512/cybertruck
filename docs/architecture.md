# 整体逻辑与目录职责

## 控制链路

```text
网页 / PC0 启停
        ↓
树莓派任务管理 ── 导航、地图、A*、定位估计
        │        扫码、物料、圆环、雷达感知
        ↓
统一设备服务（唯一 STM32 串口所有者）
        ↕ USART1
STM32 应用与保护
        ├─ 底盘执行 ─┐
        ├─ 机构执行 ─┴─ 唯一 CAN 调度 ─ 电机驱动器
        └─ IMU、PWM、TJC、PC0、PC1、PG11
```

本图描述正式任务的目标结构。2026-10-29核对：底盘闭环、连续里程计、PC0启动和机械单轴/舵机/联调已有分项实车证据；Web沿用8000入口，当前机械设备核心唯一持有STM32串口，视觉为独立采集服务。最后已烧录版本为GC-BASE-0.3.44。0.3.45新增固定观察位的底盘微调交接，仅完成离线组合验证和编译，未烧录/部署；同一MechanismLink和Bus执行空爪单轴小位移，完整实车任务及视觉成功事件仍未串联。当前先粗加工2号环微调、后机械标定，见rough_alignment_20261029.md。

0.3.45配套Pi/Web已进一步接通编号2圆环到画面中心的自动循环、后台元数据订阅和四向记录/矩阵草稿工具，离线相关回归282项、Web19组通过；本车标定尚未实测，实车自动按钮仍关闭。固定观察姿态、同一相机配置和新鲜停车后观测是复用标定的条件。整场导航到站、观察过渡和独立MISSION所有者仍须联合接入，不能把站内自动算法通过写成每次完整跑图实车通过，见rough_centering_20261029.md。

连续里程计使用共同时间区间对齐四轮计数与IMU历史，已经接入底盘执行。它是本次启动的里程计证据，不等同于外部地图配准或独立量尺精度；模型结果和实车反馈保持不同证据域。PC1两区切换、当前固件跑图入口、区1工位间隙及区2返航量尺仍按各自验收记录推进，不能从旧版本通过推定当前版本通过。

## 运行职责

树莓派负责完整任务状态机、感知结果、路径规划、定位估计、设备所有权和网页服务，维护唯一的物料与成功计数账本。浏览器是配置与观察入口，不独占自主任务保活。

STM32 负责底盘与机构动作、反馈时效、软限位、互锁、故障与停车。下位机输出状态与结果证据，上位机根据任务规则形成成功事件。

正式任务将采用待机、手动、自主、故障等运行状态，不沿用旧工程的多套编译应用选择。上位机offline/sim/serial/observer表示传输来源，不能等同于正式比赛模式。手动机械模式已经开放经确认的实车接口；任务账本仍限制模拟域，不能据此宣称真实12抓/12放已完成。

当前PC连接管理器只在用户明确连接后建立SSH和固定代理，原唯一设备核心持有STM32串口；反复连接复用有效会话，不能启动第二个串口所有者。视觉、雷达各有独立设备管理者。旧CARCAN13 observer链路属于历史迁移方案，不是当前机械调试入口；当前连接方式见`connections.md`。

动作接口区分接受、运行、完成、停车确认、失败和取消。重复消息不能重复运动或增加计数。机械联调的舵机完成仍是命令完成，没有实际角度反馈；抓持、存车、释放需额外实物证据。

## 整机接入顺序（2026-10-28原计划，10-29微调提前）

1. 修复工程配置、视觉样本完整性和帧龄；统一已知固件的协议能力与实车验收许可，二者分别判断。未知版本不得自动继承运动许可。
2. 完成0.3.43终点容差候选部署与实测，复用已保存参数；按真实误差和耗时选择两轴速度及加速度，理论时间不记作实测。
3. 同一boot/session内新增底盘与机械的显式执行权交接，保留人工零点、持续PWM和连续里程计。当前`MechPort_Owned()`使用反馈附着状态，会阻止后续底盘动作，不能仅将该判断删掉。
4. 交接必须同时解决活动底盘期间的六节点查询：现底盘活动调度只覆盖四轮，机构已建零时仍要求250毫秒反馈。先验证总线调度和保持态监督，再开放交接；不暂停时效检查或通过重建零点掩盖失效。
5. 正式任务由Pi本地持有执行权。Web人工联调的租约、离线和页面退出停止策略保留；正式任务不能直接复用浏览器租约。收拢依据用户保存的ID/修订/SHA及实物验收，不假设伸缩0毫米是运输姿态（当前已确认运输伸缩84毫米）。
6. 复用Group执行器及已保存参数，完成单件取料、存车、取出和放置，并接入对应视觉证据；旧自动Pose的49/50毫米和转臂83～180度范围不适合直接装入新手动参数。累计P00～P07检查点不得逐表重复执行。
7. 扩展三个料位、两批任务、当前版本两区跑图及雷达规划，最后按真实分段耗时优化导航60秒和整机180秒目标。各项完成条件独立记录。

当前没有部署新的执行权交接协议，也没有开放当前候选固件的实车自动规划。0.3.45离线候选实现其中的空爪固定观察姿态微调往返，协议71/72、六节点活动调度与同页按钮已实现；完整任务/持料运输交接仍待实现及验证，不能把局部微调当作完整比赛执行链。

## 执行权交接的离线设计与验收条件

以下是完整任务的设计合同，部分由0.3.45微调候选落实，不代表整个表格已完成。反馈附着、执行权和主机业务所有者需要分别表示：`attached`只表示持续观察；0.3.45局部交接以phase0/1/2及epoch区分机械、准备、底盘保持租约，主机仍为WEB_MANUAL。正式MISSION所有者待接入。一个串口、一个Link、一个boot/session及请求调度器贯穿全程，不轮换MotionLink与MechanismLink。

交接采用准备、提交、取消、只读状态四类事务。每笔绑定唯一事务ID、预期执行权代次、任务ID、零点与路线配置版本、运输合同摘要。准备失败保持原执行权和保持输出；提交应答丢失只查询结果，不重放动作。同ID改内容、旧代次、旧session拒绝。故障或状态过期撤销未提交票据，不自动重启或续跑。

运输合同必须引用未删除的保存ID/修订/SHA，明确终态检查点、五个执行器目标、载荷和实物确认记录。缺项不补0，累计版本的前五行不等于最终姿态。当前空载运输lift0/reach84/tray0/arm0/grip0不能直接当作持料运输姿态。两轴检查实际位置、目标账本、零速及反馈龄；三舵机只能核对命令与PWM保持，不能据此声称实际角度已测得。交接不得改变夹爪、PWM、人工零点或轴目标。

底盘段完成后需要正常停靠保持态：在本段完成、零速发送已确认且四轮/IMU新鲜稳定后结束活动批次，保留里程计、配置、目标和启动身份；不能调用STOP/reset或重新CONFIG代替。后者会锁定会话或初始化里程计。

已用真实Base/Bus/MechPort/Comm加合成HAL复现当前反例：静止六节点保持zero v1/fault0；仅在夹具注入拟交接的EXEC_READY与Bus_Start，四轮继续查询28次、机构查询0次，139ms后机构fault2且零点失效，CAN错误及查询超时仍为0。它证明当前活动期轴反馈饥饿，不是交接成功。原始脚本与结果在`output/handoff-audit/20261028/`，输出明确`diagnostic_only=true/feature_complete=false`。

下一候选需在唯一Bus中按时效预算安排六节点查询，同时保留匹配回包、查询超时、冷却间隔、控制发送和紧急停车优先级。保持态继续监督两轴实际值与反馈；不通过暂停250ms判定或冻结快照来保留零点。

| 联合回归 | 必须成立 |
| --- | --- |
| MECH→BASE→MECH往返 | 同boot/session、零点原始值与版本、目标账本及odom连续；PWM和夹爪不变 |
| 合同SHA/删除/检查点/载荷不符 | 拒绝交接，无新输出；旧版本和原保持状态保留 |
| 动作/未决CAN/未决查询仍在运行 | 不提交交接，不取消原事务来强行抢占 |
| ACK丢失、重复包、旧代次 | 查询可判定提交结果，无重复动作，旧命令不复活 |
| 六节点0/7/8ms及抖动回包 | 记录控制帧进展和全部受监督反馈最大龄；任一过期仍停车 |
| CAN/失联/轴保持异常 | 撤销许可，沿原路径停车，无自动松爪或续跑 |
| 浏览器退出 | 手动调试按原规则停止；已明确启动的本地任务由Pi继续负责 |
| Pi退出/重启 | 停止任务，旧票据、零点与任务不自动恢复 |
| 完整离线交接 | 配置一次、PC0一次，导航→停靠→机械→运输核对→导航→返航停车 |

## STM32 目录

| 目录 | 职责 |
| --- | --- |
| `Core/` | CubeMX 外设初始化、启动入口与中断入口 |
| `Drivers/` | HAL、CMSIS 和芯片支持文件 |
| `MDK-ARM/` | Keil 工程、启动文件与受控工程配置 |
| `User/App/` | 统一初始化、周期调度、运行状态和互锁 |
| `User/Board/` | CAN、UART、PWM 等硬件适配，封装 HAL |
| `User/Comm/` | 树莓派协议、命令解析、应答和状态上报 |
| `User/Device/` | 电机协议、IMU、屏幕、按键和蜂鸣器 |
| `User/Control/` | 底盘、双轴、机构姿态与动作确认 |
| `User/Config/` | 执行参数、单位、保护参数及硬件适配常量 |

## 参数与证据

- `.ioc` 是 CubeMX 硬件配置源；生成代码必须与它一致。
- 执行保护参数归下位机，任务地图与视觉标定归上位机；禁止两端各存一份无版本的同名有效配置。
- 旧姿态、零点、视觉参考与历史测试仅供参考，不能自动成为新任务的有效状态。
- 验证按配置、编译、通信、实物分项、完整任务分别记录。已有分项实车通过仅覆盖对应版本、会话和动作；完整任务仍待验证。
