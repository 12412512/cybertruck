## 统一坐标约定

| 坐标 | 约定与来源 |
| --- | --- |
| map | 延用旧地图方向：场地左下角为原点，+X向右侧粗加工区，+Y向上侧扫码区；地图尺寸和原点必须在实场核对 |
| base_link | 原点固定为四轮几何中心的地面投影；+X为确认后的车头、+Y为车体左侧、+Z向上；原点不随机构或载荷改变 |
| odom | 本次运行局部连续里程坐标，首次有效反馈建立；整段任务不重复清零，位置校正改变map到odom的变换 |
| 相机/雷达 | 各有相对base_link的外参；雷达离地50mm只确定高度，不能补出平移、朝向或配准 |
| Web画布 | 米到像素及Y轴反向只在显示边界处理，不改变内部物理坐标 |

地图yaw=0向右，+90度向上，180度向左，-90度向下。启停区1本轮人工朝向记录为+90度，尚需确认摆放角误差；车体中心的地图X/Y待现场尺量，不能默认恰为蓝区中心。原始IMU的零点、方向和地图yaw分开管理，不直接把0.422度填为车身地图角。

地图位移到车体位移采用R(-yaw)；车体位移到地图采用R(yaw)。旧工程Y右/顺时针正的数据只在迁移边界转换一次。树莓派管理map到odom，STM32闭环使用连续odom及带时间的本地反馈。

## 路线优化的实现顺序

1. 实测完整收拢/运输包络，量启停区1车体中心和朝向；登记轮序、驱动极性、编码器比例与IMU方向。实际ready与地图/运动已标定分开，旧Web ready=true不直接开放跑图。
2. 把旧候选图按职责迁入新工程，保留UNKNOWN/OPEN/BLOCKED及证据；正式执行只使用已验证开放道路。节点状态增加朝向和运动类型，工位朝向满足左侧机构作业方向，不将道路切向默认当作车头方向。
3. 重新生成从当前+90度姿态退出启停区的路线。只在已核验转向空间处转向，再沿车身X轴跨区；不能默认300mm启停区或400mm通道允许原地转向。短侧移/斜线仅用于经过验证的起步、路口或工位调整。
4. 每条候选线段/弧段检查完整偏心车体和运输包络的扫掠，计入定位误差与净空。斜线检查全段，不只检查两端；弧线按曲率、半径、轮速和角速度约束限速。失败时保留可行的停车转向路线，不强行圆角。
5. A*状态用道路节点加朝向，代价用含加减速、转向、停车的预计时间；时间接近时选净空更大、转向更少的路线。预览与执行复用同一规划结果，取消UNKNOWN假定开放的执行通道。
6. 接入正式唯一CAN调度、真实接收时间、故障保护和零速批次TXOK；先做有独立尺量/角度证据的短直线及小角度，再做低速斜线、单个弯道、单条道路，最后扩大为整图。旧CARCAN13没有执行本次新Track库，不以四轮RPM定时组合冒充新闭环。

结论：现在可继续实车接入与受控单段验证的准备，尚不能直接按Web整图自动运行。软件离线闭环、实际设备通信、现场几何、真反馈闭环及全图运行分别验收；本页未改变不烧录/不清故障/不自主触发运动的现有执行边界。
