# 新旧Web合并方式

2026-10-24用户提供`http://172.20.10.4:8080/`，确认这是旧运动调试台，可与新建Web合并。本轮已只读打开实页并核对对应源码，没有点击停止、控制权、运动、地图写入或封路确认。

## 统一入口与设备所有权

最终以新工程FastAPI工作台为唯一产品入口，分总览、底盘、机构、视觉、地图、任务、日志页面；复用旧成功协议、控制权、失焦释放和诊断规则，按新分层迁入，保留中文清晰交互。当前先完成真实状态与诊断合并，仍为只读阶段。

```text
本轮：新Web → 新核心observer → 旧服务GET状态 → 旧服务唯一串口 → CARCAN13
后续：新Web → 正式控制核心/任务/动作接口 → 唯一设备管理 → STM32
```

过渡期不另开串口，不把旧页面嵌入iframe，也不让浏览器绕过新核心调用旧运动POST。旧服务自带`X-Frame-Options: DENY`，且整页嵌入会产生另一套控制权/运动入口，不能完成统一调度。

最终切换时，先完成新GC在板核对、电机和IMU适配、真实停止/限位/互锁、故障回归，再在车辆静止且无活动作时交接唯一设备所有权。保留旧部署备份，关闭旧服务的串口占用，核对新所有者；不能同时自动启动两个拥有者。本轮不替换树莓派服务、不设置新自启。

## 已核对功能的合并安排

| 旧Web已有功能 | 本轮已合并/保留 | 后续实现条件 |
| --- | --- | --- |
| 四轮速度、计数、反馈时效 | 新页按地址显示源报告值/有效标记；旧age缺缓存停留时间，精确时效明确未验证 | 新设备管理补精确采集/接收时间；完成轮位、极性、比例后才显示物理轮名/位移 |
| CAN错误、UART校验、状态/停止确认 | 新页展示原状态、错误计数、冻结CAN快照及源停车结果 | 真实停止证据链接入后才允许ready；故障不自动清除 |
| 陀螺仪角度/角速度与诊断 | 保留原单位/原符号与源报告标识；精确时效未验证，不当作全局姿态 | 安装方向、比例、时间对齐实测后接连续里程计 |
| 控制权、200ms网页租约、失焦/pagehide释放 | 核对旧代码；新页仅观察是否有其他控制者，不申请租约 | 新控制核心区分手动租约与自主保活；浏览器不直接持有设备 |
| 六方向点动、四轮独立RPM、连续运动 | 旧页仍存在，新页不转发这些接口 | 统一BaseGoal、限幅、期限、动作去重、停车证据及Web按住即走/松开停止 |
| 停止请求/已停止分离 | 新页原样区分源报告和本工程证据 | 统一STOP优先通道及真实四轮停车确认；按钮必须走同一核心 |
| 名义地图、起点选择、A*预览与封路 | 旧实现只读参考，本轮不复制默认车体轮廓或写地图 | 实测包络后接同一个带朝向规划器、扫掠检查；选择起点不等于测得位姿 |
| 雷达点云、启动静态扫描、人工对应封路 | 保留为后续迁移依据，不启动扫描 | 安装/覆盖/配准验证，未知不当开放；新总览不宣称已有自动避障 |
| CSRF、同源检查、禁止缓存等 | 当前无动作POST，观察仅固定GET | 开放写接口前复用旧保护规则；新增用户/租约与参数版本核对 |
| 新任务码、状态机、成功账本 | 已在新工程模拟域实现，真实观察域不读写模拟账本 | 接入正式观测与动作确认后才推进实车任务和物理计数 |

旧页面实读显示“电机1左前已确认，2～4轮位待核对”，不能因新UI排列漂亮就默认FL/FR/RL/RR均已验证。旧方向点动属于驱动组合测试，不等于完整闭环轨迹控制。名义地图的290×270毫米仍是主体尺寸；用户已确认突出物尚待补量。

本轮可直接打开新页`http://127.0.0.1:8001/`查看真实状态；旧Pi8080尚未替换。原模拟页8000可保留，用于离线任务联调，两者运行目录与计数域分开。阶段出口和证据见[本轮记录](motion_readonly.md)。
