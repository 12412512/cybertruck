# 机械Web停止与控制权稳定性修复

2026-10-26。用户反馈点击两次后页面显示“Web请求停止”和状态未知。旧记录没有停止来源，不能从截图确定究竟是按钮、快捷键还是页面生命周期触发；当前串口核心明确以Web STOP主动锁定，并非单凭该图即可认定USB掉线。

## 已确认的软件问题

1. 旧`MechanismLink.emergency()`直接调用致命`reset()`，停止动作同时停止全部只读轮询；反馈过期后整页变未知，必须重启核心才重新取得状态。
2. 全局Space在按钮获得焦点时仍执行停止，和按钮原生空格激活相冲突。
3. 旧页面迟到的退出请求使用无所有者约束的STOP，可能影响后来取得控制权的新页面。
4. 同一个`stop()`既被模型内部错误调用，也按当前显示页面路由到实车；模型迟到的错误有可能串到机械页。

## 修复范围

- 普通Web停止、控制权过期或有效页面退出：优先发送STOP，取消未完成动作队列、释放控制权并锁定动作；保留原启动身份和协议会话，继续HEART、35/58及诊断读取。不自动重连、不自动解锁、使能、建零或重发动作。STOP的ACK不是实物停车证明，仍显示板端停车反馈。
- 真正串口异常、停止ACK超时、协议/启动身份错误：继续致命锁定，不伪报在线。
- 页面退出使用`release`，核对当前所有者与令牌；旧所有者的迟到请求返回忽略。显式急停仍可不持有控制权，不因令牌失效而阻挡急停。
- 新增有界32条停止来源记录，区分面板、顶部按钮、Space/Escape、切页、隐藏、退出、离线及租约过期；不记录令牌。
- 按钮、链接、折叠标题及输入控件上的Space保留原生操作，页面空白Space与非编辑状态Escape仍停止。模型内部停止和显式当前页停止分开。
- 页面按10Hz读取反馈；仍严格按250ms有效期禁用新动作。单次续约网络回复不明时暂停新动作，并在原1.5秒租约内核对同一控制权；明确失效则释放，不重放目标、不延长保护期限。
