# Web工作台离线联调

## 本次范围

桌面优先、手机辅助。首页改为底盘与导航工作台，旧只读页保留在
`/diagnostics`，原有HTTP/WS诊断接口保留。此次不连接树莓派、串口或ST-Link，
不修改、编译或烧录MCU固件，不触发实车动作。

当前实车仍是GC-BASE-0.3.11。此前两批9段首轮80.766秒，用户确认基本正常；
第二轮USB中断，用户确认车轮目视静止，板端停车确认未收到。接线问题尚无新的
设备验收证据。本次离线模型不能代替该链路验收，也不改变固件故障停车保护。

## 启动与使用

在工程根目录执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/start_workbench.ps1
```

脚本构建正式纯C主机模型库，启动两个隐藏进程：

- `robot.workbench.core`：127.0.0.1:8090，唯一离线执行核心。
- `robot.web.app`：127.0.0.1:8000，页面、网关和只读诊断。

打开 `http://127.0.0.1:8000/`，获取控制权后可操作。停止本机服务使用：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/stop_workbench.ps1
```

启动脚本不抢占已有端口，停止脚本核对工程、模块和父子进程身份。
日志、模型库、规划版本和PID记录位于忽略目录 `output/workbench/`。

## 所有权与故障边界

网页不持有设备对象，通过固定回环接口访问独立核心。一个浏览器持有一份随机令牌，
控制权有效1.5秒，点动帧有效350ms。只有点动本身续约才维持运动，普通renew不能替代。
客户端序号递增，同请求ID重复返回原结果；内容改变、乱序、过期令牌均拒绝。

普通松手请求 `manual_stop`，保留控制权、提高序号屏障，迟到点动不能重启。
全局停止独立发送，撤销控制权和前端普通待发队列。停止请求与模型轮速稳定分别显示。
退出页面/断网时，即使停车请求发送失败，核心仍按点动期限停车。
自动离线路线由核心调度，浏览器关闭不等于停止自动任务；全局停止可终止它。
控制循环超过100ms时请求模型停车；日志写失败不会阻止该停车路径。

规划在单个后台线程执行，不持有控制循环锁；规划草稿、最新预览和正在执行的版本
分别保存。执行中修改滑块或重新规划不会改变当前目标。规划失败保持不可执行，
不存在的计划ID不能直接运行。

HTTP动作要求同源、自定义请求头及严格参数校验；WS拒绝其他来源。
真实设备接口本次明确不可用，未知轴位置与零点返回未知，不显示假反馈。
