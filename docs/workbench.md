# PC场景与控制工作台

## 当前范围

沿用 `http://127.0.0.1:8000/` 作为后续导航、标定和机械调试的统一入口。
本轮只开发、验证PC端，手机端暂停。本页全部操控作用于离线合成车体；
真实串口、树莓派部署及MCU烧录均未执行。旧只读诊断仍在 `/diagnostics`。

当前实车仍为GC-BASE-0.3.11，原料2段、巡回6段、两批9段的实车冻结包保持原状。
此前两批首轮80.766秒用户确认基本正常；第二轮USB中断，用户确认目视静止，
板端停车确认未收到。本文新增的动态离线轨迹不能绕过其固件白名单下发。

## 启动

在工程根目录执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/start_workbench.ps1
```

脚本构建正式C主机模型，启动127.0.0.1:8090独立离线核心与8000网页网关。
不访问串口或SSH。停止本工程服务使用 `tools/stop_workbench.ps1`；
脚本检查模块、工程路径及父子进程，不抢占其他服务端口。

## 操作流程

1. 获取控制权，选择起点与任务方案，或编辑自选站点顺序。
2. 设置工位间隙、请求速度、模型轮速上限。
3. 地图操作切换为“点击添加黑色障碍”，点击场地添加；新增直径默认50mm。
4. 表格可按毫米修改障碍X/Y和直径；删除模式点击黑圈删除，也可表格逐项删除或清空。
5. 自动重规划默认开启。编辑仅规划，不会自动运行；新草稿取消旧计算。
6. 规划成功后查看路线、参考时间、速度曲线与限速原因，再显式运行离线闭环。
7. 保存版本后可读取恢复。恢复初始设置清空草稿障碍、回到默认参数及模型起点，保留历史版本。

| 设置 | 初值与含义 |
| --- | --- |
| 起点 | 启停区1，车身+X与地图+X一致；起点2为地图−X |
| 巡航速度 | 默认0.30m/s，可设0.03～1.00m/s，这是请求上限 |
| 模型轮速 | 默认100RPM，可探索20～350RPM，仅影响合成模型 |
| 工位间隙 | 原料、粗加工、暂存各50mm，独立可调；量车体面向工位外缘至工作区边缘 |
| 障碍物 | 黑色圆圈，默认直径50mm，可调10～300mm，最多20个 |
| 作业朝向 | 扫码0°、原料+Y、粗加工−Y、暂存−X，返航不要求出发朝向 |

按当前名义地图和车体，50mm对应原料O=(0.270,1.200)、粗加工O=(2.065,1.200)、
暂存O=(1.200,0.335)m。原料道路交点仍为(0.340,1.200)m，靠台点单独设置，
不会把整条车道拉斜。这些是几何规划点，尚不能证明相机、夹爪或机构已可达。

## 规划、速度与包络

两批、巡回、原料、自选站点均从当前场景重新搜索，不再用冻结轨迹假装支持障碍。
复用既有道路朝向A*，按参考时间和每段停车预留选择候选，再复用正式C连续参考平滑。
工位位置与朝向必须同时满足；不能只规划XY中心。该选择限于已有道路/朝向候选，
不声称证明了连续平面全局最优。

碰撞检查使用整个矩形车体及定位/跟踪余量。圆与凸包进行边、角及内部相交判断；
转弯按正式参考变化率界做自适应扫掠，不能只检查障碍中心或路线端点。
无法通行、工位被占用或无合法朝向时明确报告无路，不自动删除障碍、移动工位或开放未知道路。
此处模拟碰撞检查不恢复此前已取消的实车上位机地图执行门槛。

设计遵循[完整车体轮廓检查原则](https://docs.nav2.org/rolling/configuration_and_development/first_time_robot_setup_guide/footprint/setup_footprint/)
及[速度、加速度约束原则](https://docs.nav2.org/rolling/configuration_and_development/configuration_guide/core_servers/configuring_velocity_smoother/)，
实现继续使用本工程Python规划器与正式C Ref/Track/Odom。

请求1m/s不代表轨迹已达到1m/s。默认100RPM、半径50mm时，理想纯直线轮速换算仅约0.524m/s；
斜向、转姿还需分配轮速，短距离也会受V/A/J限制。页面分别显示请求值、参考采样峰值、
保守轮速界和限制原因；更高RPM只是离线假设。实车1m/s须后续按反馈、载荷、停车和精度验证。

搜索代价与显示估计共用 `SETTLE_ESTIMATE_S=1s/段`，速度曲线显示参考和预留区间，
实际闭环仍以位置、航向、低速及稳定反馈确认完成，不以参考时间结束代替到位。

## 版本、读取与重启

- `output/workbench/workspace.json`：当前草稿及最新完成路线。程序重启恢复预览和参数，不续跑。
- `output/workbench/plans/<id>.json`：显式保存的独立版本，含任务顺序、速度、工位间隙、
  障碍、地图、RefSpec、曲线、摘要。后续可直接读取用户在此界面设置的路径。
- `output/workbench/events.jsonl`：控制权、规划、版本、开始/完成及停车事件，限容量轮换。

读取时检查配置/显示轨迹校验、Spec摘要、场景一致性和整段碰撞；损坏文件拒绝读取。
旧schema1保留为历史，不能直接作为新动态场景读取。旧schema2时间预留值按保存版本保留，
重新规划后采用当前统一的时间模型。所有导出仍标记simulation/executable=false。
恢复初始设置不是删除历史版本；读取配置不是使能动作。运行时配置被冻结。

规划在后台进行，提供工位级进度；同参数缓存复用，新草稿取消旧任务。
复杂首轮搜索仍可能需要数十秒，不能把缓存命中时间冒充首次规划时间。
几何加速仅在完整包络可证明无碰撞时提前接受，其余仍执行原自适应检查。

## 操控与故障

网页不占用设备，核心是唯一离线执行者。令牌控制权1.5秒，点动帧有效350ms；
普通renew不能替代点动续约。松手、失焦、隐藏页面请求点动停车，断网后核心独立超时停车。
普通松手保留控制权，全局停止撤销控制权、提高顺序屏障，迟到点动不能重启。
请求ID去重、严格参数校验、同源保护和输入快捷键隔离继续生效；Tab/Ctrl+A等不产生运动。

自动离线路线不依赖浏览器持续开着。模型使用同一个Plant与连续里程计逐段交接，
独立2ms车体真值检查实际扫掠。碰撞、跟踪故障及控制周期异常锁存失败；
普通停止不清除模型故障，停稳后显式重置离线场景才清除。日志写失败不阻断停车。
真实固件250ms反馈过期、CAN故障、偏离及超时保护未改动。
点动与定量校准不走场地导航规划；它们不沿用上次路线的场景指针，场地扫掠验收针对规划路线。
