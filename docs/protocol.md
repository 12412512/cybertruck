# GC协议1：只读阶段

此页保留GC-RO-0.2.0历史基线。新固件GC-BASE-0.3.3增加受控短段能力，能力位为5；独立MotionLink核对该能力，默认只读Link仍要求1。新增0x20～0x23、配置52字节/目标96字节/执行状态80字节，见[执行接入](execution.md)。STOP回复成功只代表已接受停止，物理停止仍需单独状态证据。

此版用于新工程与只读控制台，不兼容旧CARCAN文本协议、旧搬运车AA55协议或CYQM雷达LR协议。复用的是COBS算法、有界解码、唯一设备所有权和时效检查，未复用旧报文语义。

## 帧格式

串口USART1，115200、8N1。原始帧按COBS编码后追加一个00；多字节整数小端，无符号。禁止直接发送C结构体内存。

| 原始偏移 | 字段 | 长度/含义 |
| --- | --- | --- |
| 0 | magic | 2字节，ASCII `GC` |
| 2 | version | 1字节，1 |
| 3 | type | 1字节；请求1～6，应答为请求类型OR 0x80 |
| 4 | boot | 8字节，设备本次启动随机身份 |
| 12 | session | 8字节，控制核心生成的随机会话身份 |
| 20 | request | 4字节，请求关联号；应答原样返回 |
| 24 | ttl_ms | 2字节，请求取1～1000，应答为0 |
| 26 | length | 2字节，负载0～128字节 |
| 28 | payload | length字节 |
| 28+length | crc | 2字节，CRC-16/CCITT-FALSE：poly 0x1021、init 0xffff、不反射、xorout 0，覆盖原始帧头和负载 |

原始帧最大158字节，编码段最大159，含分隔最大160。超长编码段丢弃至00后恢复；空分隔忽略。编码错误、错误magic/version/长度/CRC均不进入命令处理。

`ttl_ms`当前限定从接收首字节到主循环解析完成的时间，含MCU串口队列等待，按uint32毫秒差处理回绕。它不是跨机器同步后的发送端截止时间。所有运动请求仍拒绝；后续接入运动前必须定义设备时钟截止时间、动作ID和完成证据，不能仅凭此TTL启用动作。

## 请求及应答

每个应答负载第一个字节为结果，随后为数据。结果：0成功、1启动身份不匹配/不可用、2会话/代次不匹配、3设备被另一会话占用、4接收期限过期、5格式错误、6当前只读阶段拒绝执行。

| 请求 | 请求负载 | 成功应答数据（不含结果字节） |
| --- | --- | --- |
| HELLO=1 | 空，session=0，发现时boot=0 | `<II16s>`：握手代次、能力位、ASCII固件名；能力当前严格为1=只读 |
| OPEN=2 | `<I>`：HELLO取得的握手代次；boot和非零session必须匹配 | 空 |
| HEART=3 | `<I>`：控制核心推进计数 | 空 |
| STATE=4 | 空 | `<IIHIIII>`：开机毫秒、故障位、状态标志、有效保活数、设备正确帧数、设备错帧数、拒绝数 |
| DIAG=5 | 空 | `<II>`：未发送普通/紧急应答被更新次数、当前握手代次 |
| STOP=6 | 空，boot=0或本次boot，不依赖session | 返回结果6，锁存禁止标志；不表示有电机停止反馈 |

状态标志：bit0只读、bit1会话已绑定、bit2禁止标志锁存、bit3实体PC0原始电平为按下。PC0不触发任务，尚未作为消抖后的操作事件。故障位：bit0启动随机身份不可用、bit1串口接收/溢出错误、bit2串口发送错误。故障仅由新启动初始化清除，此版无网页清故障命令。

## 会话、保活与时效

1. MCU使用内部RNG生成64位启动身份。取数失败或全零时不允许OPEN；没有备用固定身份。此机制用于隔离复位前后报文，不承担认证或加密。
2. 核心HELLO后绑定本次boot及握手代次，再用随机非零session请求OPEN。另一会话在有效租约内不能覆盖当前所有者。
3. OPEN首次建立500毫秒租约；重复OPEN不续期。只有HEART的推进计数严格向前（无符号差小于半周期）才续期，重复保活不续期。普通状态查询也不续期。
4. 租约到期或UART故障使session失效并增加握手代次，旧OPEN/HEART不重新激活旧会话。MCU复位另有新boot；核心重启产生新session，并先握手核对。设备重新连接只恢复只读状态。
5. 主控只保留一个待应答请求，通过type/request/session/boot关联；迟到或无关应答不推进状态。250毫秒无应答则回到发现流程，不能重发运动。本版没有运动或机构API。
6. 正常调度为保活约10Hz、状态查询最高20Hz、详细诊断最高5Hz；单请求串行，传输慢时降频并撤销在线。网页推送10Hz。尚未实现100Hz底盘控制，不把通信频率当作CAN吞吐。

普通应答和STOP应答各有独立保留槽；普通积压不能占用STOP槽。主循环每次最多处理512个接收字节，发送用中断，已经开始的UART帧不会被截断。STOP当前仅用于测试禁止标志及应答优先级；CAN/PWM未启动，没有实物停车闭环。

## 状态可信度与进程边界

- `robot.main`是唯一串口所有者和保活推进者，默认offline；`sim`只导入演示设备，`serial`要求显式设备路径且必须匹配新固件。代码没有自动搜索串口或启动旧程序。
- 同一运行目录由OS文件锁保证只有一个核心；POSIX串口另设exclusive，Windows串口由系统独占。网页为另一进程，只读原子替换的状态快照，不导入串口管理者。
- MCU状态超过250毫秒撤销设备在线；核心快照超过500毫秒、单调时间倒退或墙钟窗口失效时，Web撤销在线/无故障/按键状态。浏览器700毫秒无推送再次撤销显示。
- 真实位姿、抓取/放置计数保持null；零点有效性和实物停稳确认保持false。显式任务演示可在`task`字段携带`domain=simulation`的任务及`simulation_counts`，不改变真实计数。模拟/离线/实机模式在页面显著区分。
- 核心事件日志按1MiB、3份备份轮换；启动身份、通信或故障位变化时保留当时的设备状态/诊断，状态快照覆盖保存。异常握手后至少间隔250毫秒重试。浏览器关闭不影响核心推进，核心停止会使MCU租约失效。

FastAPI/WebSocket接口依据[官方WebSocket文档](https://fastapi.tiangolo.com/advanced/websockets/)；串口独占与超时依据[pySerial API](https://pyserial.readthedocs.io/en/latest/pyserial_api.html)。本版仅提供GET状态与WebSocket推送，没有参数写入、建零、使能或运动HTTP接口。

接收/处理/上报时间负载V1规范见[反馈时间链](feedback_time.md)。历史能力1的type0x10仅预留；新能力5已通过Execute_Command/MotionLink开放两字节kind/address选择查询，复用56字节负载及原时效验证。CARCAN13仍不支持该新负载，新固件已烧录并通过静止只读时间链验收，见[板端记录](board_readonly.md)；实物运动仍待验证。
