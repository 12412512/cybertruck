# PC工作台与视觉采集、标定

本轮继续使用 `http://127.0.0.1:8000/`。底盘规划、机械实车控制、相机与标定、运行记录使用同一导航。机械控制仍由唯一设备核心执行；视觉页的保存接口不访问动作、使能、建零、清故障或成功计数接口。

## 页面职责

- 底盘与导航：原有地图、障碍物、路线、速度及模型联调。
- 机械控制：现有实车两轴、三舵机、回零、姿态与顺序/同时联调。
- 相机与标定：主画面保留原图比例，右侧分为采集、标定、资料；较窄的PC面板改为上下布局。服务未连接时显示原因，仍可使用旧样本。
- 运行记录：新增实车只读健康摘要与JSON导出；原模型事件保留。健康摘要复用机械页GET结果，不新增设备连接，不保存控制令牌。

切页使用统一导航，不再以点击“运行记录”模拟视觉页切换。实车停止与模型停止的按钮作用域明确；输入框、按钮的空格交互和已有停止/故障保护不改。只读连接状态不授予动作权限。

## 采集方式

1. 选择旧样本、实时相机或已保存样本，读取画面。
2. 实时预览中选择框选工具会冻结当前画面；页面隐藏、切换来源和超时会取消待返回请求，不让旧请求覆盖新选择。
3. 填样本名、观察工位、人工标签、颜色、料位和实物备注。可关联设备核心已经保存的实车姿态或联调版本（ID、修订号及SHA必须全部匹配）。
4. 保存当前图像与同帧观测。服务器只接收已缓存的帧引用，不接收浏览器上传的“实时图像”，也不在保存时另抓一帧。
5. 在资料页查看和导出JSON。读取保存样本沿用保存时的识别结果，不伪装为新帧或自动重新识别。

样本中的持料、存车、释放等文字是人工标签，`physical_validated=false`，不增加抓放计数。设备快照来自保存时刻，并不声称与曝光同步。旧样本始终保留历史来源。关联机械版本只保存引用，不执行该版本。

## 标定草稿

- 在原图坐标中框选检测ROI、抓取ROI；缩放只影响显示，坐标仍为原图像素。
- 颜色采样复用旧 `sample_color`，保存颜色模型、区域裁剪图、源图校验值和配置来源。
- 原料台、地面圆环、车载料位、码垛顶面分别保存草稿。
- 像素到毫米采用归一化DLT拟合；至少4个拟合点和1个独立检查点，建议6点以上。重复位置、退化点和超界点拒绝。
- 独立检查点不参与拟合，报告拟合最大误差、独立检查最大误差和逐点残差。结果保持 `metric_valid=false` / `applied=false`，不能直接用于实车纠偏。
- 读取旧草稿要求当前画面相机和尺寸一致，且只载入编辑区。安装、曝光、畸变、目标高度和夹爪偏置仍需现场核对，低拟合误差不替代这些验证。

## 保存与容量

数据保存在忽略目录 `output/vision/workbench/`：

- `samples/`：图像、观测、人工标签、机械版本和保存时设备快照。
- `drafts/`：ROI、平面、对应点及误差报告。
- `colors/`：颜色模型及选区图像。

每次保存产生独立ID、修订号和SHA，不覆盖旧版本。每类最多200条，图像总量最多512MiB；满额明确拒绝并提示归档，不自动删除。最近帧引用缓存最多12张、有效20分钟；失效后读取新帧或已保存样本。保存失败不报告成功，JSON临时文件与部分图像清理，已经完成的版本保留。写接口要求工作台同源头。

## 2026-10-28完整性和时效修复

样本读取先核对记录ID、JSON摘要和图像SHA，再直接返回同一次读取的字节，避免校验后重新打开文件带来的替换窗口。旧样本只要保留原外层`image_sha256`仍可回放，不重写历史数据。缓存图像转为不可变字节并绑定摘要；颜色采样和再次保存继续使用同一张已校验的缓存图像。替换、缺失、空图或超过4MiB均明确拒绝。

实时识别代理将源帧龄与本机请求耗时相加，作为保守上界；哈希、深拷贝及缓存锁等待完成后、写入缓存前最后核对250ms。响应与缓存保存同一最终帧龄，超时不留可保存引用。完整JSON中的NaN、Infinity及指数溢出也在缓存前拒绝，避免先缓存再序列化失败。Pi与PC单调时钟不直接相减；浏览器仍叠加自身往返耗时，临界帧可能更早不可用，不据此放宽250ms。原始JPEG预览端点没有帧龄元数据，本次未将其当成可执行的识别证据。
