## 任务码与计划

格式为`CCC+PPP+CCC+PPP`。颜色只允许ASCII 1～6，每批三种不同颜色，两批颜色集合相同；位置组各是123排列。第二组定义第一批粗加工与暂存位置；第四组只定义第二批粗加工位置，第二批暂存按第一层同色位置。

锁存至少三个不同帧，采集时间递增、同一流、帧龄不超过250毫秒，窗口跨度至少100毫秒且整体仍新鲜。旧帧、重复帧、未来帧、多码歧义、错误格式不推进锁存，已锁存结果不被普通后续识别覆盖。

计划顺序：准备→模拟启动→启动扫描→前往扫码→锁存任务码→第一批原料取入S1/S2/S3→粗加工放三件→取回三件→第一层暂存→第二批同样的原料和粗加工流程→同色第二层→返回所选启停区→完成。

完整计划为34步：24次转存、8次语义导航、1次扫描、1次扫码。导航只表达目标工位和顺序，没有坐标、朝向、速度、机构行程或真实路径执行；扫描只接模型的完整性结果，不能冒充雷达道路覆盖。

每件物料以批次/顺序作为账本逻辑身份，记录颜色和位置。逻辑身份不是宣称相机能读取唯一实物编号。三料位、粗加工环、第一层和第二层分别保存占用状态。第一层颜色映射仅在已确认放置后生成，第二层同时检查目标环、实际底层颜色及顶层是否占用。

## 执行与成功分离

```text
INTENT → ACCEPTED → RUNNING → EXECUTED → CONFIRMED
                     │             │
                     └── FAILED / 未知 → 等待对账或显式终止
```

- 先持久化INTENT，再允许适配器接收；接受、运行、执行结束均不增加成功数。
- PICK需要空目标槽、正确来源、正确持料、确认存车四组证据。STORED复用EMPTY的槽视图；仅“看到夹爪空”不足以确认存车。
- PLACE需要目标空置/同色底层、持料、释放、正确稳定放置四组证据。没识别到不等于空位；接地释放不等于已经正确放置。
- 每组至少三个新帧、跨100毫秒，检查相机/视图/标定、运行/会话/动作/姿态代次、时间、质量、颜色和物料归属。执行结束后仍可以等待所需确认；最终证据过期不能推进。
- 只有CONFIRMED原子更新占用与计数。动作执行中将相关料位/物料标为UNKNOWN，夹爪和运输姿态保持未确认；未知不能用于下一次跨区。
- 同一事件编号同内容重放不产生新事件或计数；同编号不同内容报冲突。换事件编号重放已结束动作也不能推进；动作编号不能重新用于下一步。
- 失败/取消不自动张爪、回零或重发。逻辑期限180秒或时钟倒退会终止本轮；这只是模拟逻辑保护，不是180秒物理验收。

## 持久账本与恢复

运行目录中的`task.sqlite3`保存两张表：`events`为带版本的事件记录，`runs`为状态投影。`(run_id,event_id)`唯一，事件写入和状态更新在同一个`BEGIN IMMEDIATE`事务中提交；失败整笔回滚。启用WAL、外键和`synchronous=FULL`，未结束任务不能另开活动轮次，每轮事件有4096条上限。

依据[SQLite事务文档](https://www.sqlite.org/lang_transaction.html)及[同步设置说明](https://www.sqlite.org/pragma.html#pragma_synchronous)实现。不将这些设置等同于树莓派SD卡、电源或文件系统已经完成掉电可靠性验收。

打开已有账本时重放事件并核对投影，不一致则保留数据并停止。未知schema不改写。核心重启若遇到未结束任务，进入`RECONCILE_REQUIRED`，保留既有计数，把待执行动作标为UNKNOWN，不自动续跑；此版没有“把未知动作当成功后继续”的入口。

当前支持明确终止模拟旧轮次后另建新轮次，旧事件不删除。新轮次使用新run_id且计数从0开始；已完成轮次重启只读查看仍保留完整结果。后续实车对账、人工核验和受控恢复适配尚未接入。

模拟域由任务创建、帧、执行结果和页面共同检查。主状态的真实`grabs/places`仍为null；仅在`task.domain=simulation`下显示`simulation_counts`。不发送计数到STM32/TJC。

## 本机操作

详细环境和Web启动见[树莓派说明](../pi/README.md)。工程根目录：

```powershell
$env:PYTHONPATH = Join-Path (Get-Location) 'pi'
.\.venv\Scripts\python.exe -m robot.task_sim --code '136+321+631+312' --start-zone 1
```

该命令使用独立`output/task-demo/`，写入账本及`task-report.json`。不填`--code`只查看已有轮次；发现未结束旧轮次时，带`--code`也不会覆盖或自动续跑。

需要Web联调时，核心使用`--mode sim --task-demo '136+321+631+312'`，Web指向相同运行目录。本次预览为`output/preview/`、`http://127.0.0.1:8000`，可用`tools/stop_preview.ps1`停止。网页没有动作、改参数、清计数或恢复任务接口。

停止核心后，显式终止待对账模拟轮次：

```powershell
.\.venv\Scripts\python.exe -m robot.task_sim --runtime output/task-demo --abort-run <run_id>
```

该操作只是结束旧任务，保留未知和历史计数；随后带`--code`创建新的模拟轮次。不能解释为确认实物状态。
