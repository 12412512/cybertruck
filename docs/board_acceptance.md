# 换板后集中验收准备

2026-10-25仅完成工具与离线验证，未连接设备。候选固件GC-BASE-0.3.21：CAN1 PD0/RX、PD1/TX，PG11低有效蜂鸣器，PE14/TIM1_CH4为预留PWM；PE9/11/13及其余配置保持既有映射。

## 默认模式不打开设备

在工程目录运行：

```powershell
.\.venv\Scripts\python.exe -B tools/accept_board.py
```

只输出准备步骤与限制。即使误加`--port`，没有`--collect`也不连接串口。分析已有记录：

```powershell
.\.venv\Scripts\python.exe -B tools/accept_board.py --analyze output/<旧记录>/acceptance_raw.json --output output/<新目录>/board_report.json
```

输出文件拒绝覆盖；历史报告始终`live=false`、`authorizes_motion=false`，不代替当前状态。

## 现场获准后集中执行

1. 烧录由独立正式工具完成：核对探针、板UID、镜像摘要，备份、写入、全字节读回；本工具不提供烧录。烧录后先通知用户，再只读检查，放地/运动另行确认。
2. 核对唯一串口所有者与正确设备；打开当前USB串口可能复位STM32，必须重新绑定boot/session，不续旧动作。
3. 使用`accept_board.py --collect --port <已核对串口> --seconds 30 --output <新目录>/board_report.json`。这里只说明未来命令，本节点未执行。
4. 必须保持DISABLED、配置版本0、动作0、无启动票据，按步骤人工拨PC1两档、松开/按PC0；读取输入电平，不执行prepare59，不使能，不发目标。若出现票据/短鸣/启动、故障或断线，验收失败，不清错续测。
5. 收集版本/身份、启动STOP、四轮速度/位置/状态、IMU、UART错误、首次里程计故障、首次CAN错误与收发历史、机构软件状态58、PC0/PC1状态60。只读命令白名单：1/2/3/4/5/16/35/36/37/38/58/60；无STOP6、CONFIG32、ARM33、GOAL34、附着48、建零50或准备59。

验收要求四轮连续反馈、0RPM、停车确认、无CAN/串口/CRC故障、无动作及PWM关闭，稳定身份和反馈覆盖率，PC1两区和PC0两种电平都有记录。采集中断先保存失败现场，禁止自动重连或清故障。

## 不包含的结论

- 状态58只是机构执行器软件快照，未附着机构时不能证明ID5/6真实CAN反馈正常；后续需受控只读附着验收，不以轮子健康推断上层两轴健康。
- PE14尚无业务执行接口；CH4初始化Pulse0及未启动PWM需结合生成源码与波形测量核对，不能靠原三路PWM掩码证明新通道电气状态。
- PG11实际极性/短鸣、舵机方向、人工零点、行程、碰撞余量及停止距离均需独立实物验收。
- 只读静止不能验证IMU动态方向/尺度，也不能证明地图配准、整机180秒或导航60秒达标。
