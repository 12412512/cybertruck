# 雷达扫描到绕障执行链：PC离线节点

2026-10-25完成。仍用原8000，换板未完成；本节点没有连接雷达/树莓派/STM32/串口/SWD，没有烧录、清故障、使能或实车动作。固件源及GC-BASE-0.3.21 HEX均未改变。

## 数据链与来源

旧`cyqm_protocol.py`的v6 COBS/CRC和完整点云组装→旧`cyqm_lidar.py`的GRID/RESULT字段→连续扫描回放检查→多帧稳定候选→模拟厂家坐标到map转换→同一工作台道路朝向规划器→`nav.bridge`冻结包→正式C的Comm/Start/Exec/Ref/Track及独立Plant。

- 雷达识别位置来自厂家RESULT，本轮做配对、质量、时序与重复观测检查；不以最多120个显示抽样点重新估计全场或推断空地。
- 复用旧03/04有界连续扫描方式。合成案例有14个独立点云和结果，设备时间跨度1.3秒，检查窗口不超过10秒；这不是07单次锁定扫描实测或“14圈已验收”。
- 合成两区分别标记`synthetic-zone-1-v1`和`synthetic-zone-2-v1`。厂家坐标到map的平移/旋转、整场道路覆盖、障碍50mm直径和10mm位置不确定度是明确的模型条件，绝非真实标定结果。离线案例的观测姿态来自夹具场景，不表示当前实车或普通模拟模型正停在该处。
- 50mm障碍加两侧位置不确定度，本轮规划圆直径70mm；多帧离散还可继续扩大不确定度。道路邻域提示不代替完整车身扫掠，仍由同一场地碰撞模型决定路径能否通过。

## 有效与拒绝条件

必须匹配节点、启停区和模拟标定；至少三个不同扫描序号的完整点云/GRID/RESULT，以及明确STOP。候选需至少三个独立结果、多帧一致、命中≥3、最低置信度≥60%、支持点≥3、位置离散≤20mm；本轮夹具为14帧一致、95%。

CRC/未知或超长帧、残留拆包、点云缺块、序号冲突、GRID/RESULT不匹配、溢出、时间戳倒退/重复、超出10秒、区号改变、未STOP或低质量目标都会拒绝进入自动规划；后续正常帧不能掩盖此前错误。不稳定或识别不到不当作空地。

未知道路加入禁止通行集合；零障碍只有完整覆盖有效时才可解释为该模拟范围空场。厂家格号不是地图道路编号。旧真实系统右侧可见、前方遮挡和未配准的限制没有因本轮合成整场覆盖而解除。

外部`.json`的`wire_hex`或纯`.hex/.txt`报文可在页面回放，最大65536字节。即使CRC和结果完整，也统一保留`external_unregistered`、未知覆盖及无真实外参，不能调用自动绕障规划。文件内的标定或“已测量”字段不会被信任。

## 原8000页面

1. 获取离线控制权，设置启停区、路线和速度。
2. 在“雷达扫描与自动绕障”选案例，点击“回放扫描”。默认有效后自动提交规划，不自动运行。
3. 地图显示转换后的抽样点、50mm黑圈、含不确定度的橙圈、障碍邻域和新绕障路线；原始抽样点可在折叠区查看。低质量/无配准显示拒绝原因。
4. 待规划成功，点击既有“执行链联调（合成PC0）”。仅内存协议与模型，不要按实物PC0。
5. 扫描绑定ID、原始报文摘要、标定版本和路线版本；改速度继承观测与障碍。替换/清空扫描或核心重启后，旧雷达路线不能执行，必须重新回放规划。改启停区前清空回放。

联调与单轴/舵机/转存互斥；取消、失去控制权和故障沿用既有停车逻辑。250ms反馈、500ms保活、CAN故障、偏离、超时及段间停车不放宽；本轮补CAN故障和反馈丢失负例，均触发失败及STOP，不重新使能/续跑；反馈故障无法证明停车时保留未确认。

原始报文、夹具配置和扫描报告归`output/workbench/lidar/<扫描ID>.json`；计划及执行记录沿用`output/workbench/execution_checks/`。所有新记录均为simulation、非实时、非物理验收且不授予运动许可；不写真实任务账本或成功次数。旧服务草稿在本次仅PC重载前已备份，原路线版本保留。
