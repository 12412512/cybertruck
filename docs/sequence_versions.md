# 机械联调版本删除

“机械联调”的保存版本旁增加“删除选中版本”。点击后显示完整名称与修订号，由用户确认，仅删除当前选中的一条版本，当前编辑表不清空、同名其他版本不删除。

删除是归档事务。Pi唯一设备核心将原记录、SHA、删除时间及请求身份原子写入runtime/physical_sequence_archive.json，保留physical_sequences.json的不可覆盖历史。列表及新视觉关联不再提供被删版本，program_run也拒绝被删版本；历史视觉样本及原关联内容不修改。同名再次保存沿历史最大修订号递增，不复用被删除编号。

不要求人工建零或无故障才能管理参数，但必须新鲜连接、无机构/联调/恢复动作正在执行；其他页面持有控制权时拒绝。删除不取得控制权，不输出UART、不使能、不建零、不重置PWM，也不取消正在执行的动作。写入失败保留原列表；同请求ID重发幂等，内容变更拒绝；归档损坏不忽略。

侧栏原箭头为旧“详细诊断”入口，日常布局已移除。它仍有技术排查用途，现收进运行记录的“高级诊断”；/diagnostics地址保留。

离线：37项Python相关验证（新增8项版本归档用例）、14组JS（新增9项删除权限）、1152工程检查通过。旧核心没有sequence_management标记时，新删除按钮保持禁用，不借网页删除绕过核心。删除是数据管理操作，网页使用最近收到的连接快照，板端核心仍在处理请求时检查其250ms有效状态；不放宽任何动作接口的时效条件。

用户明确确认机构有支撑、允许重载后，备份旧PID3173及全部版本，在原目录启动唯一PID4445；固件仍0.3.34，初始6条保存记录逐项相等。30.031秒124次只读，最大状态龄138ms、故障0/0、停车/PWM0，零点失效、两轴未附着；无自动使能/建零/目标。用户随后主动确认删除P00_运输收拢v1，已核对对应归档、SHA与完整原参数；按用户意愿不恢复。其余5条版本保留。

浏览器已改为页面内二次确认，避免原生确认框阻塞页面刷新；P01打开确认后取消通过、没有删除P01。侧栏箭头消失，运行记录的高级诊断链接展开可见。单项目标/速度刷新前副本保留在现场证据中；联调草稿未清空。小节点不单独Git。

本轮不改STM32固件、不烧录、不发送机构动作；不单独提交Git，不动docs/start2_reverse.md与独立雷达修改。当前现场快照在output/mechanism-live/sequence_delete_20261027。
