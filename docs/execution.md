## 接入与复用

链路为：树莓派MotionLink → GC会话 → Execute_Command → Exec → Track/Ref/Odom → 唯一Bus → Can → 电机。复用旧CARCAN13的can_transport、motor_bus、motor_protocol及其回归夹具，按模块迁入Device，未复制旧业务、UART/PWM初始化或多个应用入口。源文件SHA256与目标见[复用索引](can_reuse.json)。原Web定时点动不适合作100Hz位置跟踪，不能用连续HTTP点动冒充轨迹执行。

迁入后统一模块函数前缀/Allman/四空格，新增中文注释，保留纯仲裁丢失与真实CAN错误的区别、50ms原事务期限、2ms周转、取消隔离及停止优先。MotorReply补充原始CAN接收序号与首次主循环处理时间，不能每次读取缓存都重新贴时间。

App只统一调用Port/Base。Port独占USART1和USART2，IMU保留ISR字节时间、源代和解析代；CAN接收仅搬运，Bus在主循环唯一消费。Odom接真实位置/IMU时间链，执行中保持连续原点；IMU不写零、加速度不积分。GPIO、时钟、NVIC及中断入口原有配置已满足，IOC未改，不重新生成外设；CAN IRQ用户区补入错误寄存器快照，主main仍仅App初始化/调度。

## 启动与执行门槛

1. 新固件启动先向已配置的四轮地址发送STOP，防止外部驱动保留复位前RPM；没有自动使能/轨迹。待停止批次真实TXOK、四轮新速度/位置及150ms稳定证据后才接纳配置。无法确认则保持禁止动作。
2. 地址唯一来源config/base_trials.json，sync_project生成Config/addresses.h，构建核对一致。配置中的地址必须与固件启动停止地址一致；不能给未知地址试发动作。
3. 新boot/会话、显式候选配置、显式ARM和独立GOAL缺一不可。ARM逐轮使能后核对新的使能状态；不会把发送F3或等一段时间当成就绪。
4. 控制10ms计算，CAN按原四轮速度批次＋两条必要反馈安排，100Hz计算不代表100Hz整组总线。配置最多10RPM，本次候选6RPM；平移目标≤150mm、转角≤10°、总期限≤20秒，另外限制偏离动作起点≤200mm/0.22rad。
5. 首次只开放短平移与小转向，斜线复用同一平移算法但不列入首次CLI执行选项；弧线和整图请求在固件入口拒绝，不能把大路径拆包绕过本轮人工验证。
6. Track到位仍要求误差、低速、四轮本批零速TXOK及之后新反馈的150ms稳定窗口；BusSpeed入队、GC接受或参考时间结束均不算到位。停止确认还检查编码器变化，不能只看0RPM。
7. CAN/驱动错误、轮/IMU失效、控制周期>50ms、500ms核心进度保活失效、超时或取消都中止。异常不重发目标、不自动清错/续跑。正常STOP确认后仅清正常停止本地锁，回观察态，不自动使能；持续观察不重置odom。

板端总线处理时间作为保守发送屏障，只有四轮TXOK之后才产生，不冒充电机采样时刻。100Hz周期预算、停止距离、CAN吞吐和上述参数在本车仍待测，不将主机模型当M4实时性证明。

## 公共协议

保持GC1的COBS、CRC、128字节有界负载和独立STOP应答槽，HELLO能力5、固件名GC-BASE-0.3.0。旧CARCAN13文本协议不兼容本入口；不向旧固件试发新命令。

| 请求 | 负载/语义 |
| --- | --- |
| 0x20 CONFIG | 52字节，小端：version、三项几何float、layout uint32、每圈计数float、yaw_sign int32、角度/陀螺尺度float、max_rpm float、4地址、4命令极性int8、4反馈极性int8；只接受未使能配置或同一配置的重复查询，不重建相同odom |
| 0x21 ARM | 空；接受后进入使能状态，仍未执行目标 |
| 0x22 GOAL | 96字节：id/timeout uint32＋88字节RefSpec；目标相对动作启动时车体；同ID同内容只查原状态，不重执行；冲突/倒退/忙拒绝 |
| 0x23 EXEC_STATE | 空；返回80字节：11个uint32＋9个float，模式/故障/动作ID/状态/停止确认/板时/配置版本/CAN信息/odom有效性，以及局部位置/航向/误差/四轮命令RPM |
| 0x10 FEEDBACK | 两字节kind/address，返回既有56字节V1时间负载；保存ISR接收、首次处理、上报时间和源代。未配置时也可读取原始IMU，不推断符号或物理采样时间；过期/缺失返回拒绝，不能用旧缓存装新反馈 |
| STOP=6 | 可抢占普通请求；接受与反馈确认分开；迟到ACK不触发重发 |

Comm不绑定执行器时仍是原只读能力1，保留既有协议回归。MotionLink以独立新鲜性显示原始IMU和接收时间；MCU接收时刻不等于传感器内部采样时刻。

## 树莓派与Web入口

默认命令仅打印准备内容，不打开串口、不访问实车：

```powershell
$env:PYTHONPATH = '.\pi'
.\.venv\Scripts\python.exe -B -m robot.drive_core --case straight
```

side为左移80mm、turn为逆时针10°。首次straight为前进100mm，限制线速0.03m/s、角速0.10rad/s，均按6RPM候选档核对。每次显式选择一个目标，结束后请求STOP并核对新停止状态，原始意图、接受、状态、取消与结果写output独立新JSONL；不修改抓取/放置账本。结果名controller_complete不替代尺量。

真实执行需要明确串口、--execute、--accept-candidate和本次--site-ready，并补齐yaw_sign。旧Web服务只要仍可访问就拒绝接管，即使其connected=false；网络状态不确定也拒绝，不自动停止旧进程。新串口打开仍复用禁止主动DTR/RTS复位和独占设置。命令丢ACK后停止、只查询，不自动重发；重连恢复观察，未决动作记未知。

用户已答IMU方向暂不确定，配置yaw_sign=null，打开串口之前即拒绝。旧几何0.05/0.094/0.11m来自声明，不当成本车标定；量程同样为待核对候选。此处不要求用户现在转动车辆，实测前再用已确认方法判断方向。

为烧录后先做无动作基线，新增--observe：明确串口与旧服务已释放后，仅HELLO/OPEN/HEART/状态/原始反馈查询，不发送CONFIG/ARM/GOAL/STOP；未知yaw_sign也可观察原始值。它不自动移交所有权，本轮未运行该实车模式。由新固件自身执行的启动STOP已在烧录说明中明确，不与主控观察请求混为一谈。

8000新增加实车短段准备区，显示未连接新固件/未下发/待停止反馈，不设网页运动按钮；/api/base/trials只读给出同一准备表。原场地图与84.29秒模型保持离线，executable=false；真实执行核心可通过自己的runtime挂同一只读Web，执行快照也有独立250ms失效处理。
