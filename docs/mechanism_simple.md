# 精简机械页与工位流程

2026-10-25，沿用原8000。仅PC离线：未连接设备、未烧录、未清故障或触发实车动作，固件/引脚/控制参数不变。

## 主界面

- 五行独立控制：升降电机、伸缩电机、转臂、料盘、夹爪。各行显示模型值、目标与执行按钮；只校验本行目标，编辑不启动动作。轴为mm、舵机为度，在统一接口换为米/弧度。
- 同一组五个目标直接用于姿态预览、保存和联调，不重复填写五套目标。联调调用已有`Mechanism._pose_steps`，先收回/抬升再旋转和伸出，逐步完成，不同时开放五轴。
- 默认收起工位流程、旧候选、单步选项、点动、互锁记录、转存、实车接入和历史记录；原功能保留。实车面板改为明确按需加载，默认不轮询设备代理。
- 原0～49/50mm、转臂83～180°、料盘0～270°、夹爪0～98°及保夹/旋转/伸出互锁不变。PE14仍为预留，不加入这三只舵机或默认PWM。

先获取控制权、确认离线域、建立模拟零点并锚定估计；原升降最高/伸缩最近端基准保持不变。每行点执行只操作该执行器，若互锁未满足则明确拒绝。输入和保存均不会运动。

## 保存姿态和工位流程

1. 填五行目标，取姿态编号/名称，预览并保存新版本。保存沿用`output/workbench/mechanism_poses.json`，保留旧记录。
2. 读取保存版本再点“联调选中姿态”；改过草稿必须先保存，不能把新草稿当作旧版本执行。需要张爪时显式勾选本步释放，仅模拟。
3. 展开“工位流程与路线报文”，选择当前路线的到位点，把选中的冻结姿态按顺序加入。到位点通过正式参考终点与扫码/原料/粗加工/暂存坐标及朝向匹配，不按任意线段或显示名称猜测。
4. 下一导航段前加入收拢姿态；多次访问同一工位按导航段号区分。保存流程版本，再读取、逐姿态联调或编译候选包。

工位流程的逐姿态联调只运行机构模型，底盘不动；不声称已在该实际工位，亦不构成整图或抓放成功验收。运行时持有唯一机构所有权，拒绝插入单轴、转存或导航动作；底盘故障、250ms反馈失效、零点变化、失去控制权及停止会取消，不自动回零、张爪或续跑。

流程保存为`output/workbench/mechanism_programs/<编号>-v<版本>.json`：绑定路线ID/摘要、机构配置摘要、每步插入位置、姿态ID/版本/SI目标/摘要、允许模型释放标记。版本拒绝覆盖；当前列表最多30条，历史文件保留。重启只读记录，不恢复有效零点或继续未完成步骤。编辑中的流程引用另保存在浏览器本机草稿，不能当作冻结版本。

## 正式格式候选报文

“编译路线报文”写入`output/workbench/mission_candidates/<ID>.json`，可由后续工具或助手直接读取：

- 复用`nav.bridge.prepare`校验导航路线及扫掠，生成34号底盘目标。
- 将工位姿态插入相应导航到位点后，生成55号姿态载荷模板；SI转换与实车编码器共用`device.mechanism.pose_body`，不复制一套单位换算。
- 姿态模板42字节，包含8字节会话令牌/零点前缀及34字节正式姿态体；前缀为0，动作ID也必须在未来执行时重新绑定。完整GC帧的boot/session/TTL及顺序等运行身份尚未填入，不是可直接发送的实车帧。
- 每步带停车、工位位置、反馈、有效零点、无故障、实车示教及舵机确认条件；下一导航段带运输包络和物料运输确认条件。
- 按同一机构互锁预检整个姿态序列；缺少收拢、版本/配置/路线变化、姿态校验损坏均拒绝编译。

候选包固定`domain=simulation`、`executable=false`、`physical_validated=false`，不进入真实串口发送队列，不自动建零/使能，不增加真实成功计数。原实车`payload('pose',...)`的`physical_taught`门槛保留，模型示教不能借由共用编码器获得实车权限。实车接入仍须新PCB验收、真实姿态与几何验证及受控运行时绑定。
