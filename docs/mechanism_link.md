Web → 固定回环代理 `/api/device` → 唯一 `robot.mech_core` → 新会话二进制协议 → `Board/mech_port` → 正式Axis/Servo/Pose → 唯一Bus / TIM1。

设备核心默认site_ready=false；本次烧录后未收到现场确认时禁止任何使能/建零/PWM/目标。仅取得本次确认后才可显式使用--site-ready。启动只读，不自动附着机构、不使能、不建零、不启动PWM。48接入后查询ID5/6的完整驱动配置及35/36/3A/33反馈；人工使能与人工建零另发命令。底盘使能/轨迹与机构接入互斥。本版不开放真实连续点动，仅开放受限定距、舵机命令和逐步姿态。

## 保护

- 启动/STOP停止地址包括1～6；CAN真实故障锁存保持。驱动配置核对为200步、16细分、固定校验；仅查询，不写配置。
- 轴和底盘真实反馈250ms保护不变，主控500ms保活不变。
- 网页控制权1.5秒；页面隐藏/退出请求STOP，租约失效后核心STOP并失效会话。失联不自动重连或重放动作。
- 每条机构修改携带单调操作编号。相同编号相同载荷只返回结果，冲突拒绝；ACK表示接受，轴到位须新反馈，PWM等待结束须独立人工确认。
- 物理姿态先逐通道确认首次PWM，再允许姿态组合。每个姿态步骤由板端预检与互锁控制，不由浏览器拼接轴命令。
- 人工建零基准：升降最高、伸缩最近端。没有实体限位；49/50mm保留初始软件范围。
- 实车示教保存到设备运行目录`physical_poses.json`，按编号/版本/摘要冻结；仍标为待实测，不增加任务成功计数。
- 不设清故障入口。故障或会话失效后先只读取证，不能通过新开浏览器恢复执行。

## 协议

48附着（只读机构反馈），49显式单轴使能，50人工建零，51舵机参考记录，52单轴目标，53舵机目标，54人工姿态确认，55冻结姿态目标，56单步放行，57失效并停止，58只读状态。所有请求保留现有boot/session/TTL/COBS/CRC。

修改请求前8字节为小端`操作编号uint32 + 零点版本uint32`；48第二字段为固定标记0x4D454348。应答为COMM结果后跟机构原因uint32；58返回28个uint32，字段见`pi/robot/device/mechanism.py:FIELDS`。物理公共输入为米/弧度，边界转微米/毫度；真实舵机角度始终未知。

## 运行

在树莓派已有虚拟环境中，保持旧串口所有者停止，显式指定已核对by-id设备：

```text
PYTHONPATH=pi python -B -m robot.mech_core --serial /dev/serial/by-id/已核对的设备 --runtime output/runtime --port 8091
```

与旧drive_core共用`output/runtime/core.lock`，串口还使用系统exclusive打开。只监听127.0.0.1；PC通过SSH本地转发8091使用，不公开控制端口。PC原8000 Web代理只访问本机8091，不直接操作串口。

重载PC网页服务后刷新现有页面才会出现新入口。设备服务未启动或SSH隧道未建立时入口显示未连接；不自行扫描设备。

## 验收边界

离线夹具验证的PWM应用只是合成HAL调用；Keil通过和烧录读回均不等于机构到位。实车需要烧录后新一轮只读验收及用户当次放地/机构条件确认，再逐轴/逐舵机验收。CAN问题未解决时保持锁存，禁止动作。
