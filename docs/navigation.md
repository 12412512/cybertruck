# 坐标、路径规划与离线导航验收

2026-10-24；从`cc572b7`推进，本节点`v0.9.0-navigation-sim`。用户明确：完整实物赛场、启停区1、车头朝扫码区，且蓝色区域可以行驶。本轮只实现新工程离线计算/模拟/Web，没有打开真实串口、烧录、清故障或发送实车动作；两个旧参考工程只读，Pi8080未替换。

## 本轮行为

地图固定为左下原点、X向右、Y向上；车体固定为四轮几何中心地面投影、X前/Y左，偏航逆时针正。`nav/frames.py`统一SE(2)组合、逆变换、旧Y右/顺时针边界和画布翻转。连续角不因每段动作归零；显示同时给出归一化地图朝向和展开角。

启停区1本轮起始航向为+pi/2，不再使用旧预览0。模拟中心仍取名义(0.15,2.25)m，**不是已测车位**；真实中心、摆放误差和map到odom配准仍未知。地图变换只应用到模拟odom，顶层真实pose保持null。

**蓝区是可行驶地面标记，不是禁行区。** 新规划器不再禁止途经另一蓝区，也支持两蓝区之间的条件预览；当前导航巡回仍从1出发、回1。场地外边界、黄区及工作台包络照常检查。旧8080中的蓝区限制没有直接改写，当前统一结果在新本机Web展示；本轮约定覆盖旧记录里“蓝区途中禁入”的结论。

## 配置与文件职责

| 位置 | 唯一职责 |
| --- | --- |
| `config/field_preview.json` | 版本nominal-map-2；名义地图、车体四边偏置、净空、节点、候选道路及工位朝向，全部标为simulation/未实测 |
| `pi/robot/nav/frames.py` | 统一坐标，米/弧度；不读设备、不把图标当定位 |
| `nav/reference.py` | 正式C Ref的绑定及本轮合成调试速度；不复制曲线、弯道或运动学公式 |
| `nav/geometry.py`、`field.py` | 凸包/SAT、偏心矩形、旋转/弯道区间包络及地图数据域校验 |
| `nav/planner.py` | 节点＋四种车身朝向A*、连续角、共线合并、可行弧段局部替换 |
| `pi/robot/route_sim.py` | 同一正式C里程计/跟踪器与独立Plant逐段闭环，固定地图目标转换、到位屏障和真值扫掠 |
| `web/static/navigation.js` | 同一计划/结果的只读地图、车身朝向、过程/终点与路段表；不另建规划器 |
| `tests/test_navigation.py` | 坐标、路线、扫掠、道路状态、闭环和Web验收 |

车体模拟仍仅用用户报告的290×270主体，前后/左右对称偏置是模型假设，完整突出物、载物包络和实际偏心均未测。普通路段按20mm净空加12mm追踪预留检查。蓝区终端内部因300mm格与290mm主体余量很小，只检查名义主体不越场界，不宣称具备普通路段的32mm余量；转动仍查完整扫掠，不能用此例外跳过转弯检查。

工作台几何沿用旧名义地图。为保证模拟旋转净空，粗加工预停点改为(2.0,1.2)、暂存预停点(1.2,0.40)、西侧通行线X=0.34、南侧Y=0.33m；这些是新候选值，不是现场测量或已验证机械可达距离。原料/粗加工/暂存车头分别为+90/-90/180度，使左侧机构朝工作区；扫码朝向及全部外参仍待实测。

## 规划与弧线选择

1. 未提供道路证据时所有道路UNKNOWN，不可通过；BLOCKED同样排除。演示显式构造“无新增障碍、候选道路OPEN”的合成场景，始终返回executable=false。正式部署请求直接NOT_READY。
2. A*状态含节点和朝向，可选择前进、倒车及经扫掠检查的±90度转向；跨区道路只沿车身X轴。出入启停区及工位连接允许最多0.3m短斜移/侧移，不把长横移当作常规跨区路线。
3. 代价用正式C参考时长加每段1秒停稳/修正估计；倒车乘1.08、短移乘1.25。几何距离除巡航速度作启发式。共线段在连续odom里合并，减少无意义停车。
4. 对连续同向的“直线→90度转向→直线”，尝试半径40/60/80/100/120/160/200mm的正式C平滑路径。逐个检查空间、角V/A/J及理论轮速；仅保留预计更快的可行候选，否则保留停车转向并记录拒绝原因。

这是带朝向全局选路后做局部弧段优化，不声称对所有连续曲线组合求得全局时间最优。新道路编号与旧Web不同，旧封路结果不自动按名称或镜像迁入，避免误配准。默认本机没有自动雷达封路或真实地图定位。

## 采样间的扫掠保护

复用旧凸包/SAT思想并扩展旋转，不仅检查中心线或采样端点。正式C新增`Ref_Bytes/Time/Bounds`主机接口：Path每格七次多项式在t∈[0,1]时，导数系数绝对值和给平移导数上界；常数导数项减去余项绝对值和给非零切向下界。由`|yaw_s|≤|r'×r''|/|r'|²`得到航向变化率界，不能证明分母非零就拒绝候选。

上位机把每个参考区间的`(平移速率界＋带净空角点半径×航向速率界)×dt`作为世界方向膨胀量，再做完整矩形与场界/障碍SAT，另加20微米数值余量；区间自适应到膨胀不超过约1.5mm。实际弯道位置与导数仍来自同一份正式C参考，不另造圆弧公式。此包络覆盖数学模型，不能代替真实尺寸、传感器采样延迟、打滑及定位不确定度验收。

独立Plant继续按2ms积分四轮滞后/差异，每个2ms段根据该模型轮速端点上界检查实际模拟车体；检测的是模拟真值，不以参考位置覆盖真值。软件到位仍要求零速批次确认、发送后新反馈、低速/角速/编码器稳定及150ms窗口。逐段只更新目标，不新建里程计；失败冻结现场结果，不把取消或零速命令当作已停稳。

## 本轮模拟与Web

默认仅导航巡回：启停区1→扫码→原料→粗加工→暂存→启停区1；不执行扫码、抓放或两批任务，不增加物理成功计数。保留既有独立模拟账本12/12用于观察，但与本巡回不构成搬运联动。

最终23/23动作完成，含出区/工位短移与一处160mm平滑弯道；其余转角按约束保留停车转向。参考估计从134.705s降为129.808s，实际模型逻辑耗时130.970s；末段返航单独用0.025m/s，其余直线0.14m/s，弧线还按半径限速。上述是合成调试档位，**导航本身尚不满足60秒预算，不能声称整机180秒通过**。

最终模拟真值约(0.14929,2.25061)m、航向90.58度；全程origin_ms=30未改变，每个动作均有独立零速确认和至少150ms新反馈稳定。模型未进入场外或禁入工作台/黄区；实车pose/grabs/places均null，实际可执行标志一直false。

开发中保留失败记录：最初4mm追踪预留不足，暂存短侧移减速时有约6mm偏移；另一次快速返航在蓝区边界保护处失败。随后增加预留、调整名义通行线及工位转向位置，返航末段降速，没有放宽场界、停车时效或成功标准。失败证据在`output/navigation/failed-return-fast.json`及开发报告，不只保存最好结果。

Web已用浏览器核对蓝区、黄区、地图坐标轴、起点+90度、参考/实走轨迹、车身、逐段类型、23/23完成、原点和未验证项。HTTP/WebSocket仅推送，POST执行端点不存在；核心快照失效撤销有效显示。演示目标5倍逻辑速度且每轮最多16步，耗时始终显示模拟时间，不用墙钟加速效果冒充实车性能。

长巡回显示另外保留整轮有界原始轨迹（240秒期限、10ms周期），只对显示做0.5mm容差的RDP简化，保留闭环中间转角；控制和2ms真值碰撞检查不依赖简化点。已修复原有反复二分压缩使中间路段消失的问题，新增闭环图形与全场覆盖回归。

## 运行与验收命令

```powershell
.\.venv\Scripts\python.exe -B tools/build_odom.py --output output/native/navigation.dll
$env:PYTHONPATH = Join-Path (Get-Location) 'pi'
.\.venv\Scripts\python.exe -B -m robot.route_sim --library output/native/navigation.dll
```

报告默认`output/navigation/report.json`。`--blocked <道路编号>`可重复指定，验证封路或明确无路；初始两蓝区朝向可在测试中独立检查，只有启停区1朝向来自本轮用户确认。

联合Web先用`tools/stop_preview.ps1`停本机8000模拟，在两个终端设置PYTHONPATH后分别运行：

```powershell
.\.venv\Scripts\python.exe -B -m robot.main --mode sim --route-library output/native/navigation.dll --runtime output/preview
.\.venv\Scripts\python.exe -B -m robot.web.app --runtime output/preview --port 8000
```

不重复指定`--task-demo`即可保留既有账本。`--route-library`与独立`--track-library/--odom-library`互斥，offline/serial/observer一律拒绝，不自动打开串口或构建库。Windows库被预览进程持有时换输出文件，或只停止相应本机模拟后重建。Pi服务和8001观察未更改。
