# PC机械远程控制页

2026-10-26。按用户要求，原8000的`#mechanism`改为纯实车控制页，不再展示或调用离线机构模型。

## 界面及接口

- 顶部显示固件、故障、停车、零点、PWM和动作被限制的原因。
- ID5升降、ID6伸缩分别输入绝对毫米目标及RPM；PE9料盘、PE11转臂、PE13夹爪分别输入角度后执行。料盘0/30/150/270度按钮只填写草稿。
- 现场确认、两轴使能、人工建零及当前舵机参考保留。输入不动作，首次参考记录不输出PWM。使能请求被板端接受后，本页禁用该轴重复使能；这不是驱动器实际使能反馈。
- 实车姿态保存、读取和逐步调用放在折叠区；保存继续使用唯一核心的版本文件，不迁入原离线示教历史。PE14不开放。
- 请求显示具体执行器、接受/拒绝及中文原因；舵机命令完成时突出人工确认入口，等待确认的板端时限未改变。

链路仍是浏览器→`/api/device/state`与`/api/device/command`→原8091唯一核心→STM32。机械页不调用`/api/workbench`，不读取导航模型作为实物位置，不连接串口，不新增设备所有者。

`workbench-mechanism.js`只负责挂接实车页；`workbench-device.js`管理请求与界面；`workbench-remote-state.js`提供纯状态/参数规则。旧离线实现和数据未删除，但不再由本机械页挂接；底盘导航页保持其原职责。

## 保留的保护

250ms反馈时效、故障锁存、现场许可、唯一控制权/1.5秒租约、零点及姿态版本、待应答屏障和板端互锁继续检查。目标超限、空值、非有限值和非法RPM在页面与核心分层拒绝。网络结果不明确时不自动重发。停止按钮立即停止本页续约；切走机械页、浏览器隐藏/退出、断网释放控制权并请求STOP，未知停止结果不伪报已停。

机械页顶部停止按钮和非输入框中的Space/Escape均指向实车停止；重新点击当前机械导航项不会额外停止。页面加载仅GET，不取得控制权、不建零、不启PWM、不自动恢复会话。

## 本次验证与限制

88项远程界面纯规则检查、73项原提示/互锁规则、15项实车API协议回归通过。浏览器原8000已刷新；DOM核验五个实车执行按钮齐全、原模拟零点/转存入口为0。点击30度再恢复0度仅改变目标和提示，未点击控制权、使能、建零或动作按钮；页面控制台无错误。截图归`output/workbench/remote_mechanism_20261026/remote.png`。

当前本机设备代理无法取得实车状态，树莓派SSH握手亦未成功；页面如实显示未知并禁用执行，不用模拟状态补位。本轮未重启设备核心、未清故障、未烧录、未发送实车动作；之前PE9同角度保持和后续CAN0x800分别见`mechanism_stable.md`，不因界面改版升级为机构稳定验收。

本次仅静态网页更新，原8000刷新即可，无需运行服务重载脚本。恢复硬件调试时仍先核对当次固件、故障、停车、零点及现场条件。
