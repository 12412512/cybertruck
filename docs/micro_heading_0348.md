## 旧代码复核

核对旧`智能搬运小车/User/Config/drive_cfg.c`、`User/Chassis/kinematics.c`及`User/Device/motor/protocol.c`：FL/FR/RL/RR地址1/2/3/4，命令和反馈各转换一次{+1,−1,+1,−1}；旧Y右/顺时针转换到当前Y左/逆时针后公式一致。

当前+Y理论轮速为[−1,+1,+1,−1]，协议轮速为[−1,−1,+1,+1]，负Y反号；不是四只电机协议方向完全相同。旧协议同样将F6同步标志设0并逐轮发送，没有可直接复用、已验收的硬件同时起停入口。本轮保留唯一Bus/Drive和原方向/IMU极性，不擅加广播同步命令。6ms发送跨度不等于实际起停差，更不能单独解释全部偏航。

## 修复

1. config10航向容差从0.035rad（约2°）收紧至0.0034906585rad（0.2°）。正常跑图的参数不变。以260mm杠杆举例，0.2°对应约0.91mm横向分量，仅为几何预算，不是整机精度证明。
2. 同一配置会话固定首个微调动作的观察航向，不把每次残余偏角重新当成下一次的零误差。位置目标仍从真实当前位置按原车体坐标生成，不伪造位置或修改里程计。
3. 非零小步新增发送票据：从四轮整批真实TXOK后开始40～200ms小步计时。适配器必须同时匹配动作、序号和四轮协议RPM；入队成功不算发送成功。错误动作、旧票据、早于请求的ACK及重复ACK不推进。未在250ms内收到匹配发送确认仍失败停车。
4. 保留整组同幅1RPM及原斜率、零速TXOK、新反馈/编码器稳定150ms后再修正；四轮仍为顺序CAN帧，不宣传为硬件同时启动。停车发送后新反馈确认仍是最终证据。
5. 增加每动作最多224个50ms样本的RAM诊断，记录理论指令、实际发出协议RPM、逐轮TXOK时刻、实际RPM/累计计数及各自反馈时刻、IMU/误差/阶段。完成或故障冻结，GET/STOP不覆盖；下一次新动作才重新记录。不增加UART/CAN轮询负载，不能把50ms采样精度宣传为物理同时采样。

诊断工具`tools/read_micro_trace.py`必须传实际已烧录的归档目录；仅attach/read，不停核、复位或写入。尚未烧录.48时不可对旧板使用新符号。
